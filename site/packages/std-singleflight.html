std/singleflight

#concurrency

import std/singleflight

Group[K, V] with do, do_shared, forget and in_flight, which run one call per key while the others wait for its result. Expiring[V], a value refreshed at most once per interval.

Imports std/sync, std/time/clock, std/time/duration.

Types

Expiring

pub struct Expiring[V] {
    ...
}

A value that is refreshed on demand and reused until its time to live runs out.

When the value is stale, the first fetch runs the refresh and concurrent callers wait for that one result, so the refresh runs at most once per interval at a time. An Expiring is a handle: copies share one state, and every operation is safe to call from several green threads.

cached

pub fn cached[V](e: Expiring[V]) -> V?

Returns the value if one is stored and fresh, or none otherwise.

Never refreshes and never blocks on a refresh in progress.

fetch

pub fn fetch[V](e: Expiring[V]) -> V

Returns the value, refreshing it first if there is none or it is older than the time to live.

When a refresh is already running, waits for it and returns its value. Otherwise the caller runs refresh on its own green thread, outside the lock, and stores the value with the time the call started. refresh cannot fail; encode failure in V. A refresh finishing after invalidate is returned to its callers but not stored.

invalidate

pub fn invalidate[V](e: Expiring[V])

Discards the stored value so the next fetch refreshes.

A refresh already running still returns its value to the callers waiting for it, but does not store it.

refresh_count

pub fn refresh_count[V](e: Expiring[V]) -> i64

Returns the number of refreshes that have finished.

Group

pub struct Group[K: Hash, V] {
    ...
}

A set of calls in flight, keyed by K, that runs at most one call per key at a time.

While a call for a key is running, other callers with the same key wait for its value instead of running their own. A Group is a handle: copies share one state, and every operation is safe to call from several green threads. The group keeps nothing once a call finishes, so it does not cache.

do

pub fn do[K: Hash, V](g: Group[K, V], key: K, f: fn() -> V) -> V

Runs f for key once across concurrent callers and returns the value.

Behaves as do_shared without the shared flag.

do_shared

pub fn do_shared[K: Hash, V](g: Group[K, V], key: K, f: fn() -> V) -> Shared[V]

Runs f for key unless a call for key is already in flight, in which case waits for that call and returns its value.

The first caller for a key runs f on its own green thread; later callers block until it returns and receive the same value. f runs outside the group's lock. The result's shared field is true for every caller when any caller joined the flight. If f panics, the key stays in flight until forget is called and joined callers wait indefinitely.

followers

pub fn followers[K: Hash, V](g: Group[K, V], key: K) -> i64

Returns how many callers have joined the in-flight call for key, not counting the one running it.

Returns 0 when no call is in flight. The count includes callers that have joined and are still waiting for the call to return.

forget

pub fn forget[K: Hash, V](g: Group[K, V], key: K)

Stops treating the in-flight call for key as current, so the next do for key starts a new call.

Callers already waiting still receive the value of the call they joined. Does nothing when no call is in flight.

in_flight

pub fn in_flight[K: Hash, V](g: Group[K, V], key: K) -> bool

Returns true if a call for key is in flight and has not been forgotten.

pending

pub fn pending[K: Hash, V](g: Group[K, V]) -> i64

Returns the number of keys with a call in flight.

A success or failure value, for a Group whose calls can fail.

do returns V only, so a call that can fail uses Result[T, E] as V and every caller sharing the flight receives the same outcome.

expiring

pub fn expiring[V](ttl: duration.Duration, c: clock.Clock, refresh: fn() -> V) -> Expiring[V]

Returns an Expiring that calls refresh to produce its value and keeps the value for ttl, measured on c's monotonic clock.

Nothing is fetched until the first fetch. A ttl of zero or less never counts the value as fresh, so every fetch that is not joining a refresh runs refresh. A ttl too large to represent in nanoseconds never expires.
