How a value that lies between two multiples of a unit is rounded to one of them.

A value that is exactly a multiple is never changed. The first four modes ignore the position of the value between the multiples. The Half modes round to the nearer multiple and differ only in which way an exact midpoint goes.

up

pub fn up(mode: Rounding, negative: bool, even: bool, r: i64, divisor: i64) -> bool

Returns whether mode takes the upper of the two multiples around a value.

r is how far the value is above the lower multiple, from 0 to divisor exclusive, and divisor is the distance between the multiples. negative says the value is below zero and even says the lower multiple is an even multiple of the unit. An exact multiple (r of 0) returns false.

Functions

apply

pub fn apply(q: i64, r: i64, divisor: i64, mode: Rounding) -> i64

Returns q or q + 1, whichever mode selects for a quotient q with remainder r of a division by divisor.

q is the floored quotient and r is in 0 to divisor exclusive. A quotient below zero counts as a negative value for the modes that depend on the sign.

remainder

pub fn remainder(secs: i64, nanos: i64, m: i64) -> i64

Returns the remainder of secs * 1000000000 + nanos divided by m, from 0 to m exclusive.

The sum is never formed, so the result is exact where it would overflow i64. nanos is expected to be from 0 to 999999999, and m must be positive.
