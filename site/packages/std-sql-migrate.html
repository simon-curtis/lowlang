std/sql/migrate

#database

import std/sql/migrate

Ordered migrations recorded in a schema_migrations table with a SHA-256 checksum: plan, with_table, status, up, up_to and down, each migration in its own transaction under a lock. from_text and load_dir read -- +up and -- +down files named NNN_name.sql.

Imports std/crypto/hash, std/file, std/io, std/slices, std/sql, std/text, std/time/clock, std/time/timestamp.

checksum

pub fn checksum(m: Migration) -> str

Returns the SHA-256 digest of the migration's up statements as lower-case hexadecimal.

Each statement is hashed with its length, so moving text between statements changes the result. The version, name and down statements are not covered.

An ordered list of migrations and the table that records which have been applied.

Build one with plan. A Plan is a copyable value; with_table and with_clock return a changed copy.

validate

pub fn validate(p: Plan) ! Error

Checks that the plan's versions are at least 1, unique and ascending.

Fails with Invalid for a version below 1, Duplicate for a repeated version, or OutOfOrder for a version below its predecessor. Every operation that takes a plan calls it first.

with_clock

pub fn with_clock(p: Plan, c: clock.Clock) -> Plan

Returns p that stamps applied_at with c.

with_table

pub fn with_table(p: Plan, table: str) -> Plan

Returns p recording applied versions in table.

The table name is quoted for the connection's dialect. The migration lock is derived from the name, so plans with different tables do not block each other.

pub fn down(c: sql.Connection, p: Plan, steps: i64) -> []i64 ! Error

Reverts the latest steps applied migrations on c and returns the versions reverted.

See down_on.

down_on

pub fn down_on(h: sql.ConnectionHandle, p: Plan, steps: i64) -> []i64 ! Error

Reverts the latest steps applied migrations of p through h and returns the versions it reverted, highest first.

Validates the plan, takes the migration lock and creates the migration table as up_to_on does. Before reverting anything it fails with Unknown for an applied version missing from the plan and NoDown for one without down statements. Each migration is reverted in its own transaction together with the removal of its record, so a failure returns Failed and leaves the earlier reversions in place. Reverts nothing when steps is 0 or less or nothing is applied.

from_text

pub fn from_text(version: i64, name: str, source: str) -> Migration ! Error

Parses migration text into a Migration with the given version and name.

The text has an -- +up section and an optional -- +down section. Statements end at a line that ends in ;, and may span lines. A statement containing semicolons, such as a function body, goes between -- +begin and -- +end lines, which makes everything between them one statement. Blank lines and comments between statements are dropped, and a final statement without ; is kept. Fails with Syntax at the offending line for text before -- +up, a missing -- +up, a misplaced -- +begin or -- +end, a section change inside a block, or a block left open.

load_dir

pub fn load_dir(dir: str) -> []Migration ! Error

Reads every NNN_name.sql file in dir as a migration and returns them in ascending version order.

NNN is the version and name the label, split at the first underscore. Files without the .sql suffix are ignored and subdirectories are not searched. Fails with BadName for a file that does not fit the pattern, Duplicate for a repeated version, Syntax for malformed text and Io when the directory or a file cannot be read.

up_to_on

pub fn up_to_on(h: sql.ConnectionHandle, p: Plan, version: i64) -> []i64 ! Error

Applies the pending migrations of p up to and including version through h and returns the versions it applied, in order.

Validates the plan, takes the migration lock, creates the migration table if it is missing, and releases the lock before returning; a failed release fails with Sql unless an earlier error is returned instead. The lock is a session advisory lock on Postgres, an application lock on SQL Server that waits for the holder, and absent on SQLite. Fails with Drift if an applied migration's checksum no longer matches and OutOfOrder if a pending migration is below the highest applied version. Each migration runs in its own transaction with its record, and is skipped if another session recorded it first, so a failure leaves earlier migrations applied and returns Failed for the failing one. Returns an empty list when nothing is pending.
