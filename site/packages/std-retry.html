std/retry

#concurrency

import std/retry

Policy with attempts, base, multiplier, maximum delay, Jitter (None, Full, Equal, Decorrelated), a deadline, a seeded Rng and a cancel token. delay; a loop driver start with next (reserve then commit) and at_least; run over a Step (Done, Retry, RetryAfter, Fatal) giving an Outcome.

Imports std/cancel, std/rand, std/time/clock, std/time/duration.

Examples

flaky_api

import std/retry
import std/time/clock
import std/time/duration
import std/time/timestamp

enum ApiError {
    Unavailable
    RateLimited
    NotFound
}

fn name(e: ApiError) -> str {
    match e {
        Unavailable => "503 unavailable"
        RateLimited => "429 rate limited"
        NotFound => "404 not found"
    }
}

fn reason(s: retry.Stop) -> str {
    match s {
        Running => "running"
        Exhausted => "attempts used up"
        Deadline => "deadline reached"
        Cancelled => "cancelled"
    }
}

fn report(outcome: retry.Outcome[str, ApiError]) {
    match outcome {
        Value(body) => print("  result: {body}")
        Failed(e) => print("  failed: {name(e)}")
        GaveUp(e, why) => print("  gave up on {name(e)}: {reason(why)}")
        Stopped(why) => print("  stopped before the first attempt: {reason(why)}")
    }
}

fn policy(time: clock.Manual) -> retry.Policy {
    retry.policy()
        .with_base(duration.milliseconds(100))
        .with_multiplier(2.0)
        .with_jitter(retry.Jitter.None)
        .with_clock(time.clock())
        .on_retry(fn(attempt: i64, wait: duration.Duration) { print("  attempt {attempt} failed, retrying in {duration.to_string(wait)}") })
}

/// Retries a simulated API call on a manual clock, so waits are recorded instead of slept, and shows each way the loop can end.
fn main() {
    print("recovers after two failures:")
    let time = clock.manual(timestamp.epoch())
    report(retry.run(policy(time), fn(attempt: i64) -> retry.Step[str, ApiError] {
        match attempt {
            1 => retry.Step.Retry(ApiError.Unavailable)
            2 => retry.Step.RetryAfter(ApiError.RateLimited, duration.seconds(2))
            _ => retry.Step.Done("42 records")
        }
    }))
    print("  waited in total: {duration.to_string(clock.elapsed_since(time.clock(), duration.zero()))}")

    print("never recovers:")
    let down = clock.manual(timestamp.epoch())
    report(retry.run(policy(down).with_attempts(3), fn(attempt: i64) -> retry.Step[str, ApiError] {
        retry.Step.Retry(ApiError.Unavailable)
    }))

    print("not retryable:")
    report(retry.run(policy(down), fn(attempt: i64) -> retry.Step[str, ApiError] {
        retry.Step.Fatal(ApiError.NotFound)
    }))

    print("deadline of 250 ms:")
    let slow = clock.manual(timestamp.epoch())
    report(retry.run(policy(slow).with_attempts(10).with_deadline(duration.milliseconds(250)), fn(attempt: i64) -> retry.Step[str, ApiError] {
        retry.Step.Retry(ApiError.Unavailable)
    }))

    print("manual loop:")
    let r = retry.start(policy(clock.manual(timestamp.epoch())).with_attempts(3))
    for retry.next(r) {
        print("  attempt {r.attempt}")
    }
    print("  stopped: {reason(r.stop)}")
}

How a retry loop backs off, built from policy and the with_ functions.

The wait before attempt n + 1 is the backoff delay(p, n), randomised by jitter. Every field has a default, so Policy {} is the same as policy(). A Policy is a copyable value; the with_ functions return a changed copy.

delay

pub fn delay(p: Policy, attempt: i64) -> duration.Duration

Returns the backoff delay after attempt number attempt, before jitter.

The base delay is grown by multiplier once for every attempt after the first and capped at max_delay, so attempts 1 or lower return base, or max_delay when that is smaller.

jittered

pub fn jittered(p: Policy, attempt: i64, previous: duration.Duration, mut r: rand.Rng) -> duration.Duration

Returns the wait after attempt attempt with the policy's jitter applied, drawing from r.

previous is the last wait, which only Decorrelated uses. With None the result is delay(p, attempt); with Full it is between zero and that delay; with Equal it is between half of it and all of it.

on_retry

pub fn on_retry(p: Policy, f: fn(i64, duration.Duration)) -> Policy

Returns p that calls f before each wait with the number of the attempt that just ended and the wait about to start.

It is not called for the first attempt or when the loop stops instead of waiting.

run

pub fn run[T, E](p: Policy, op: fn(i64) -> Step[T, E]) -> Outcome[T, E]

Calls op with the attempt number until it returns Done or Fatal or the policy stops the loop.

Attempts count from 1. Retry and RetryAfter wait as next does. Returns Value for Done, Failed for Fatal, GaveUp with the last error and the Stop reason when attempts, deadline or cancellation end the loop, and Stopped only when the loop stopped before the first attempt.

start

pub fn start(p: Policy) -> *Retrier

Returns a retry loop for p that has made no attempts yet.

Starts the deadline clock. Without a policy rng, the loop seeds its own random generator.

with_attempts

pub fn with_attempts(p: Policy, attempts: i64) -> Policy

Returns p allowing attempts attempts in total, the first included.

Values below 1 become 1, which makes one attempt and no retries.

with_base

pub fn with_base(p: Policy, base: duration.Duration) -> Policy

Returns p with base as the delay before the first retry.

A negative base becomes zero.

with_cancel

pub fn with_cancel(p: Policy, t: *cancel.Token) -> Policy

Returns p that stops when t is cancelled.

The token is checked before each attempt and after each wait, and a wait ends early when it is cancelled.

with_clock

pub fn with_clock(p: Policy, c: clock.Clock) -> Policy

Returns p measuring elapsed time and waiting on c.

with_deadline

pub fn with_deadline(p: Policy, total: duration.Duration) -> Policy

Returns p limited to total time from start.

A retry whose wait would end past total is not made and the loop stops with Deadline. The time already spent in an attempt counts.

with_jitter

pub fn with_jitter(p: Policy, jitter: Jitter) -> Policy

Returns p using jitter to randomise each delay.

with_max_delay

pub fn with_max_delay(p: Policy, max_delay: duration.Duration) -> Policy

Returns p with max_delay as the largest delay between attempts.

A negative max_delay becomes zero.

with_multiplier

pub fn with_multiplier(p: Policy, multiplier: f64) -> Policy

Returns p with multiplier as the factor the delay grows by after each attempt.

Values below 1.0 become 1.0, which keeps the delay constant.

with_rng

pub fn with_rng(p: Policy, r: rand.Rng) -> Policy

Returns p drawing jitter from r, which makes the waits reproducible for a seeded generator.

Retrier

pub struct Retrier {The number of the current attempt, counting from 1, or 0 before the first call to next.    pub attempt: i64Why the loop ended, or Running while next can still return true.    pub stop: StopThe wait before the current attempt, which starts as the policy's base delay.    pub last_delay: duration.Duration
    ...
}

The state of a retry loop, driven by next.

Read attempt inside the loop for the current attempt number. A Retrier is a pointer returned by start; it is not safe to share between green threads.

at_least

pub fn at_least(r: *Retrier, d: duration.Duration)

Raises the wait before the next attempt to at least d, for a server-requested delay such as Retry-After.

The floor applies to one wait only, and the jittered delay is used if it is longer. The deadline still applies to the raised wait.

commit

pub fn commit(r: *Retrier) -> bool

Carries out the wait planned by the last successful reserve and starts the next attempt.

It calls the observer, blocks the green thread for the wait and returns true, or returns false with stop set to Cancelled when the token was cancelled during the wait. The first attempt starts at once without a wait or the observer.

elapsed

pub fn elapsed(r: *Retrier) -> duration.Duration

Returns the time since start, on the policy's clock.

next

pub fn next(r: *Retrier) -> bool

Waits and returns true when the caller should make the next attempt, or returns false once the loop has stopped.

It is reserve followed by commit. The first call returns true at once. Later calls return false with stop set to Cancelled when the token is cancelled, Exhausted when the attempts are used up, or Deadline when the wait would pass the deadline. Otherwise they call the observer, block the green thread for the wait and return true, or return false with Cancelled if the token was cancelled during the wait. Once false is returned, every later call returns false.

reserve

pub fn reserve(r: *Retrier) -> bool

Decides whether another attempt may follow the current one and plans its wait, without waiting.

Returns false with stop set to Cancelled when the token is cancelled, Exhausted when the attempts are used up, or Deadline when the wait would pass the deadline. Otherwise it returns true and commit carries out the wait. Call at_least first to raise the planned wait. Before the first attempt reserve returns true and commit makes it; use it when the caller must check the plan, as for a deadline, before it discards work that the retry replaces.

Step

Retry(E)The attempt failed with this error; try again after at least wait, or the backoff delay if that is longer.    RetryAfter(E, duration.Duration)The attempt failed with this error and must not be retried.    Fatal(E)
}

What one attempt asks run to do next.

Stop
