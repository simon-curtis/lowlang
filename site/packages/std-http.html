std/http

#net #web

import std/http

Server types: Request, Response, Header, header helpers and parse_url. Request.token is cancelled when the client goes away and when the handler returns. Request.remote is the client's IP address for connections served by serve, serve_tls and serve_conn. Serving: serve, serve_tls, serve_conn and serve_stream; the _on forms (serve_on, serve_tls_on, serve_conn_on) take the listener's or connection's view. Client: a pooled client configured through client() and with_* builders, per-request builders, send, stream_to and download. with_interface binds every connection to a network interface. with_resolver substitutes for net.lookup on host names; TLS keeps the host name for SNI and certificate checks. with_cancel makes a request fail with Cancelled once its token is cancelled. URLs: parsing, resolution and encoding. connect returns a droppable Connection that closes its stream when released; detach hands the stream on. Proxies: with_proxy, with_http_proxy, with_https_proxy, with_no_proxy, with_proxy_from_environment and with_dialer send requests through an http:// proxy (absolute-form for http targets, CONNECT for https targets) or a socks5://, socks5h://, socks4:// or socks4a:// proxy. no_proxy follows Go's matching rules. CookieJar is a shared RFC 6265 jar (cookie_jar, with_cookie_jar, jar_set, jar_header, jar_cookies, jar_clear) that enforces the Secure rules and the __Secure- and __Host- prefixes and has no public-suffix check. A Response whose stream is a chan[[]u8] is written as it is produced, chunked on HTTP/1.1 and as DATA frames on HTTP/2, until the handler closes the channel.

Imports std/base64, std/cancel, std/compress/brotli, std/compress/deflate, std/compress/zstd, std/crypto, std/crypto/x509, std/file, std/io, std/json, std/net, std/os, std/serde, std/socks, std/sync, std/text, std/time, std/time/date, std/tls.

Ambient

pub struct Ambient {The observer that receives the server and client events of this task, or none for no observation.    pub observer: *Observer?
}

The value at the start of a task's context slot that the HTTP server and client read to find an Observer.

__context() reads the running green thread's context slot as an *Ambient, and spawn copies it to child tasks. A task whose slot is not set, or whose observer is none, is not observed. A program that sets the slot must make its context type begin with an Ambient.

Builder

pub struct Builder[K] {
    ...
}

A configuration under construction: a client when K is Client, a single request when K is Response.

client() returns a Builder[Client] and build turns it into a Client. request returns a Builder[Response] that send, stream_to or download runs. Each with_* function returns an updated copy and leaves its argument unchanged. The functions that are generic in K apply to either kind; the rest apply to one. A request starts with the client's headers, timeout, connect timeout, redirect limit, retry count, version, prior knowledge and decompression settings. The fields are private.

let client = http.client().with_timeout(5000).with_retries(2).build()
let resp = client.request("POST", "https://example.com/items").with_text("hello").send() catch {
    _ => return
}

build

pub fn build(b: Builder[Client]) -> *Client

Returns the Client for the settings in b.

The settings are copied, so later changes to b do not reach the client. When b has a jar from with_cookie_jar the client uses it; otherwise with_cookies gives it a new private jar, and without either it keeps no cookies. No connection is made until the first request.

download

pub fn download(b: Builder[Response], path: str) -> Response ! Error

Sends the request and writes the body to the file at path, creating it or truncating it.

The returned response has an empty body. The file is written whatever the status, so call ensure_success on the result and remove the file for a status that is not wanted. When the request fails part way, the file is removed. A file that cannot be created fails with Io(Denied), whatever the cause.

proxy_for

pub fn proxy_for(b: Builder[Client], url: str) -> str

Returns the proxy that a client built from b would use for a request to url, as scheme://host[:port] without credentials.

Returns an empty string when the request goes direct: no proxy is set for the scheme, with_no_proxy matches the target, url does not parse, or the configured proxy is not a valid proxy URL.

send

pub fn send(b: Builder[Response]) -> Response ! Error

Sends the request and returns the response with its whole body read into Response.body.

Blocks until the body has arrived. Any status is a success; use ensure_success to treat other than 2xx as an error. Redirects, retries, cookies and decompression follow the settings of the builder. The response has the final url, the version it arrived on, and any trailers. A response to HEAD, 1xx, 204 or 304 has an empty body. A body over 64 MiB fails with a TooLarge cause. Failures are the variants of Error.

stream_to

pub fn stream_to(b: Builder[Response], sink: fn([]u8) ! io.Error) -> Response ! Error

Sends the request and passes the body to sink in chunks as it arrives, without holding it in memory.

The returned response has the status, headers, url, version and trailers but an empty body. sink is called after redirects have been followed and decompression applied, and its failure fails the request with Io, closing the connection. Failures are the variants of Error.

Sets the authorization header to Bearer followed by token.

with_body

pub fn with_body(b: Builder[Response], body: []u8, content_type: str) -> Builder[Response]

Sets the request body to body and the content-type header to content_type, replacing any earlier body or body reader.

with_body_reader

pub fn with_body_reader(b: Builder[Response], source: *io.Reader, content_type: str) -> Builder[Response]

Sets the request body to be read from source as the request is sent, with the content-type header content_type, replacing any earlier body.

The length is not known in advance, so the body is sent with chunked transfer coding on HTTP/1.1 and as DATA frames on HTTP/2. source is read once, so the request is never retried and a 307 or 308 redirect is not followed. A read error from source fails the request.

with_cancel

pub fn with_cancel[K](b: Builder[K], token: *cancel.Token) -> Builder[K]

Sets a token that, once cancelled, aborts the request.

The connection in use is closed and the request fails with Cancelled, whatever it was doing. Set it on the builder returned by request; a token set on a client builder is not carried to its requests.

with_connect_timeout

pub fn with_connect_timeout[K](b: Builder[K], millis: i64) -> Builder[K]

Sets the time limit for the TCP connection to the target, or to the proxy, in milliseconds.

A connection that is not established in time fails with Timeout. The time left under with_timeout also bounds it. Name lookup and proxy negotiation are not counted. 0, the default, sets no limit of its own.

with_cookie_jar

pub fn with_cookie_jar(b: Builder[Client], jar: CookieJar) -> Builder[Client]

Gives the client the shared jar jar, so that several clients can use the same cookies. It takes precedence over with_cookies.

with_cookies

pub fn with_cookies(b: Builder[Client]) -> Builder[Client]

Gives the client its own cookie jar, which stores the cookies from every response and sends matching ones with every request.

Cookies set by a redirect response are kept for the following hop, and a cookie header set on the request is sent before the jar's cookies. with_cookie_jar takes precedence.

with_decompression

pub fn with_decompression[K](b: Builder[K], on: bool) -> Builder[K]

Sets whether the client asks for and decodes compressed responses, true by default.

When on, a request without an accept-encoding header sends gzip, deflate, br, zstd, and a body with content-encoding of gzip, x-gzip, deflate, br or zstd is decoded. The response then has no content-encoding header, and send sets content-length to the decoded length. A body that cannot be decoded fails with Decode. When off, no header is added and the body is returned as received.

with_dialer

pub fn with_dialer(b: Builder[Client], d: net.Dialer) -> Builder[Client]

Sets d to open every connection the client makes, in place of resolving the host and connecting directly.

d.dial receives the host name and port of the target or, when a proxy is used, of the proxy. with_resolver, with_interface and with_connect_timeout do not apply to connections it opens, and it must resolve names itself. TLS and any proxy negotiation still run over the connection it returns.

with_form

pub fn with_form(b: Builder[Response], fields: []Field) -> Builder[Response]

Sets the request body to fields encoded as application/x-www-form-urlencoded, with that content-type.

with_groups

pub fn with_groups(b: Builder[Client], groups: []i64) -> Builder[Client]

Sets the TLS key exchange groups the client offers, as IANA named group numbers in preference order.

The default is 0x11EC (X25519MLKEM768), 0x001D (X25519), 0x0017 (secp256r1) and 0x0018 (secp384r1).

with_header

pub fn with_header[K](b: Builder[K], name: str, value: str) -> Builder[K]

Sets the header name to value on every request, replacing any header of that name, ignoring case.

The name is sent as written. On a client builder the header is a default for all its requests; on a request builder it replaces the client's header of that name for that request. A name or value that is not valid fails the request with Io(Invalid). Headers the client adds itself, user-agent, accept, accept-encoding and authorization from the URL's user information, are skipped when one of that name is set.

with_http_proxy

pub fn with_http_proxy(b: Builder[Client], url: str) -> Builder[Client]

Sets url as the proxy for http requests only, in the forms accepted by with_proxy. An empty string means no proxy for http.

with_https_proxy

pub fn with_https_proxy(b: Builder[Client], url: str) -> Builder[Client]

Sets url as the proxy for https requests only, in the forms accepted by with_proxy. An empty string means no proxy for https.

with_idle_timeout

pub fn with_idle_timeout(b: Builder[Client], millis: i64) -> Builder[Client]

Sets how long an unused pooled connection is kept, in milliseconds, 90000 by default.

A connection idle for longer is closed rather than reused, and a background sweep closes them while the client has connections.

with_insecure

pub fn with_insecure(b: Builder[Client]) -> Builder[Client]

Turns off verification of server certificates, so that any https server is accepted and the connection can be intercepted. Use it for tests only.

with_interface

pub fn with_interface(b: Builder[Client], device: str) -> Builder[Client]

Binds every connection the client makes to the network interface named device, for example eth0. An empty name, the default, leaves the choice to the system. It does not apply to connections opened by with_dialer.

with_json

pub fn with_json[T](b: Builder[Response], value: T) -> Builder[Response]

Sets the request body to value serialized with json.serialize, with content-type set to application/json.

with_max_connections_per_host

pub fn with_max_connections_per_host(b: Builder[Client], n: i64) -> Builder[Client]

Limits the open HTTP/1.1 connections the client keeps to one host to n.

A request over the limit waits until a connection is free, or fails with Timeout when the request time runs out. 0, the default, sets no limit. HTTP/2 requests share one connection per host and are not counted.

with_multipart

pub fn with_multipart(b: Builder[Response], parts: []Part) -> Builder[Response]

Sets the request body to parts encoded as multipart/form-data, with a content-type that names a random boundary.

Each part is held in memory; use with_body_reader to send a large body.

with_no_proxy

pub fn with_no_proxy(b: Builder[Client], list: str) -> Builder[Client]

Sets the targets that bypass any proxy, from the comma-separated list, replacing an earlier list.

Entries are trimmed and compared case-insensitively, and empty entries are ignored. * matches every target. A host name such as example.com matches that host and its subdomains; .example.com and *.example.com match subdomains only. host:port restricts the entry to that port. An IP address matches that address, and a CIDR range such as 10.0.0.0/8 matches IP address targets inside it. A host name is not resolved to test it against an IP address or range.

with_prior_knowledge

pub fn with_prior_knowledge[K](b: Builder[K], on: bool) -> Builder[K]

Sets whether plain http requests start HTTP/2 directly, without negotiation, false by default.

Only enable it for servers known to speak HTTP/2 over cleartext. It has no effect with with_version set to Http1.

with_proxy

pub fn with_proxy(b: Builder[Client], url: str) -> Builder[Client]

Sets url as the proxy for both http and https requests.

The URL can use http://, socks5://, socks5h://, socks4:// or socks4a://; a value without :// is read as http://. User name and password in the URL authenticate to the proxy: as Proxy-Authorization: Basic for an http proxy, as username and password for SOCKS5, and as the user id for SOCKS4. The SOCKS proxy resolves the target host name. An empty string means no proxy. A URL that does not parse or has another scheme is not rejected here; each request fails with InvalidUrl holding the proxy text.

A URL without a port uses port 80, including for SOCKS proxies. An http proxy receives http requests in absolute form, always over HTTP/1.1, and is sent CONNECT for https requests. A CONNECT answered with 407 or 403 fails the request with Connect(Denied), and any other non-2xx answer with Connect(Refused). Targets matched by with_no_proxy bypass the proxy.

with_proxy_from_environment

pub fn with_proxy_from_environment(b: Builder[Client]) -> Builder[Client]

Sets the proxy and bypass list from the environment, replacing any earlier proxy settings.

http_proxy, https_proxy and no_proxy are read, with the lowercase name taking precedence over the uppercase one. all_proxy supplies the proxy for a scheme whose own variable is unset. An unset or empty variable leaves that setting empty. The variables are read when this is called, not when requests are made.

with_query

pub fn with_query(b: Builder[Response], name: str, value: str) -> Builder[Response]

Appends name=value to the query of the request URL, percent-encoding both parts.

Existing query parameters, including repeated names, are kept.

with_redirects

pub fn with_redirects[K](b: Builder[K], max: i64) -> Builder[K]

Sets how many redirects a request follows, 10 by default.

Responses 301, 302, 303, 307 and 308 with a location header are followed. 301, 302 and 303 turn the request into a GET with no body, except that HEAD stays HEAD; 307 and 308 repeat the method and body, but a request with a body from with_body_reader is not followed and its redirect response is returned. authorization, cookie and proxy-authorization are dropped when the target has another origin. A request that has used up the limit fails with TooManyRedirects, and a location that is not an http or https URL fails with InvalidUrl. 0 or less returns every redirect response as it is. Response.url holds the final URL.

with_resolver

pub fn with_resolver(b: Builder[Client], resolver: fn(str) -> [][]u8 ! io.Error) -> Builder[Client]

Sets the function that turns a host name into addresses, in place of net.lookup.

It is called for the target host, or for the proxy host when a proxy is used, and returns the addresses to try in order. TLS still uses the host name for SNI and certificate checks. A failure from it is a connection failure. It does not apply to connections opened by with_dialer.

with_retries

pub fn with_retries[K](b: Builder[K], n: i64) -> Builder[K]

Sets how many times a failed request is sent again, 0 by default.

A request is retried only when its body can be replayed, so not with with_body_reader. A failed connection attempt is retried for any method. For GET, HEAD, PUT, DELETE, OPTIONS and TRACE, a connection that resets, closes early, times out or breaks after it opened, and a response with status 429, 502, 503 or 504, are also retried. A TLS handshake failure is not. The first retry waits 100 ms and each later one doubles the wait, up to 6.4 s, or the whole seconds in a retry-after header when that is longer, up to 30 s. A retry that would not fit in the time left under with_timeout is not made, and the last failure or response is returned.

Separately from this setting, a replayable request on a pooled connection that the server had already closed is sent once more on a new connection.

with_roots

pub fn with_roots(b: Builder[Client], roots: []x509.Certificate) -> Builder[Client]

Sets the certificates that server certificate chains are verified against. With an empty list, the default, the system roots are used.

with_text

pub fn with_text(b: Builder[Response], body: str) -> Builder[Response]

Sets the request body to the bytes of body, with content-type set to text/plain; charset=utf-8.

with_timeout

pub fn with_timeout[K](b: Builder[K], millis: i64) -> Builder[K]

Sets the time limit for a request, in milliseconds.

The limit covers the whole request: connecting, sending, redirects, retries and reading the whole body, including time spent in the stream_to sink. A request that exceeds it fails with Timeout and its connection is closed. 0, the default, sets no limit.

with_tls

pub fn with_tls(b: Builder[Client], config: tls.Config) -> Builder[Client]

Sets the TLS configuration for https connections, replacing the earlier one including with_roots, with_insecure and with_groups.

The client overwrites config.alpn with the protocols it negotiates, and uses the host of the request as config.server_name when that is empty.

with_user_agent

pub fn with_user_agent[K](b: Builder[K], agent: str) -> Builder[K]

Sets the user-agent header. Without it the client sends lowlang-http/1.

with_version

pub fn with_version[K](b: Builder[K], v: Version) -> Builder[K]

Sets the HTTP version to use. Http2, the default, offers HTTP/2 and falls back to HTTP/1.1 when the server does not accept it; Http1 always uses HTTP/1.1.

HTTP/2 is negotiated through ALPN on https and is not used through a forwarding proxy. Plain http uses HTTP/2 only with with_prior_knowledge.

Client

pub struct Client {
    ...
}

A pooled HTTP client, made by build.

It keeps HTTP/1.1 connections alive and reuses them after a response has been read in full, and sends concurrent requests to an HTTPS host, or to any host with with_prior_knowledge, over one multiplexed HTTP/2 connection when the server accepts it. It is safe to use from several tasks. It holds no drop: idle connections are closed after the idle timeout or by close_idle. Its fields are private.

close_idle

pub fn close_idle(c: *Client)

Closes the idle pooled connections of c.

HTTP/1.1 connections that are idle are closed, and an HTTP/2 connection is closed once its in-flight requests finish. Requests in flight are not interrupted, and later requests open new connections.

CookieJar

pub struct CookieJar {
    ...
}

An in-memory store of cookies that follows the Set-Cookie and Cookie rules of RFC 6265.

Copies of a CookieJar share one store, and the store is safe to use from several tasks. The jar holds at most 4096 bytes of name and value per cookie, 1024 bytes per attribute value, 50 cookies per domain and 3000 cookies in total; storing past a limit evicts the least recently accessed cookie. Expired cookies are discarded on the next read or write.

A client uses a jar through with_cookie_jar, or a private one through with_cookies.

jar_clear

pub fn jar_clear(j: CookieJar)

Removes every cookie from the jar.

jar_cookies

pub fn jar_cookies(j: CookieJar) -> []Cookie

Returns a copy of every unexpired cookie in the jar, in storage order. Changing the returned slice does not change the jar.

jar_header

pub fn jar_header(j: CookieJar, url: str) -> str

Returns the value of the Cookie header for a request to url.

The value is the matching name=value pairs joined by ; . A cookie matches when its domain and path match the URL and, for a Secure cookie, the scheme is https or wss. Cookies with longer paths come first, then older cookies. Returns an empty string when url does not parse or no cookie matches.

jar_set

pub fn jar_set(j: CookieJar, url: str, set_cookie: str) -> bool

Stores the cookie described by a Set-Cookie header value, as received in a response from url.

Returns true when the cookie is now in the jar. Returns false, leaving the jar unchanged, when url does not parse, when the value has no = or an empty name, when the name and value exceed 4096 bytes, when Domain does not cover the host of url, when Secure is set for a URL that is not https or wss, when a __Secure- or __Host- prefix rule is broken, or when the cookie would replace a Secure cookie from a URL that is not secure. A cookie that is already expired (Max-Age of 0 or less, or a past Expires) deletes the matching cookie and returns false.

resolve

pub fn resolve(base: Url, reference: str) -> Url ! io.Error

Resolves reference against base, following the rules of RFC 3986.

Leading and trailing whitespace and any fragment are removed from reference first. An absolute reference is parsed on its own, and one starting with // takes the scheme of base. An empty reference returns base. A reference starting with / replaces the target, one starting with ? replaces only the query, and any other reference is joined to the directory of the base path. Dot segments are resolved. The relative forms keep the host, port and userinfo of base.

Fails like parse_url when the reference is absolute and does not parse.

parse_url

pub fn parse_url(s: str) -> Url ! io.Error

Parses an absolute URL of the form scheme://[user[:password]@]host[:port][/path][?query].

Any scheme is accepted. The scheme and host are lowercased, the fragment is dropped, and the target is normalised as described on Url.target. An empty or absent port uses the default for the scheme.

read_request

pub fn read_request(r: *io.Reader) -> Request ! io.Error

Reads one HTTP/1 request from r, including its whole body.

Blocks until the request is complete. Blank lines before the request line are skipped. The returned request has version Http1, whatever the version in the request line, its authority taken from the host header, and connection set to r. The body is read from chunked transfer coding, or from content-length bytes; a request with neither has an empty body. When the request carries expect: 100-continue, HTTP/1.1 100 Continue is written to the stream beneath r before the body is read.

Fails with Eof when the input ends before a complete request, Malformed for a request line that is not METHOD target HTTP/1.x, a header line without a valid name and :, a bad chunk size or a content-length that is not a number, Unsupported when the version is not HTTP/1.0 or HTTP/1.1, and TooLarge for more than 100 headers, a line longer than the reader's buffer, or a body over 64 MiB. Header names are lowercased.

read_response

pub fn read_response(r: *io.Reader, method: str) -> Response ! io.Error

Reads one HTTP/1 response from r, including its whole body.

method is the method of the request being answered. Blocks until the response is complete. Interim 1xx responses other than 101 are skipped. The body is empty for a response to HEAD and for 1xx, 204 and 304; otherwise it is read from chunked transfer coding, from content-length bytes, or, when neither is present, until the peer closes the connection. Chunked trailers are read and discarded. The returned response has version Http1 and an empty url.

Fails with Eof when the input ends early, Malformed for a status line that is not HTTP/1.x and a three-digit status, a bad header, a bad chunk size or a content-length that is not a number, and TooLarge for more than 100 headers or a body over 64 MiB.

serve

pub fn serve(l: net.Listener, handler: fn(Request) -> Response) ! io.Error

Accepts connections from l and serves each on its own task, calling handler for every request.

Blocks until accepting fails and returns that error; it never returns otherwise. The server speaks HTTP/1.1 with keep-alive and, on plain connections, HTTP/2 to a client that opens with the HTTP/2 connection preface. Requests on one HTTP/1 connection run one after another; requests on an HTTP/2 connection run concurrently. A request that cannot be parsed is answered with 400, a body or header block that is too large with 413, and an unsupported protocol version with 505; any other read or write failure ends that connection without a response. Errors on one connection never reach the caller.
