std/quic/recovery

#net

import std/quic/recovery

RFC 9002 loss detection and congestion control with no I/O: recovery makes a Recovery that on_sent, on_ack, on_timeout and discard_space drive per packet number Space. It keeps the RTT estimate, declares packets lost by packet and time thresholds, runs the probe timeout and NewReno with persistent congestion, and answers can_send, deadline and pto_duration. skip records a packet number left unsent, and an ACK covering one fails Malformed.

Imports std/io.

Examples

congestion_window

import std/io
import std/quic/recovery

const ms = 1000000

fn send(r: *recovery.Recovery, from: i64, count: i64, time: i64) {
    for n in from..from + count {
        recovery.on_sent(r, Application, recovery.Sent { number: n, time, size: 1200, ack_eliciting: true, in_flight: true })
    }
}

fn report(label: str, r: *recovery.Recovery) {
    print("{label}: window {r.congestion_window} in flight {r.bytes_in_flight} srtt {r.smoothed_rtt / ms} ms")
}

/// Drives the loss detector by hand with a simulated clock: a round trip in slow start, then a loss that halves the window.
fn main() ! io.Error {
    let r = recovery.recovery(1200)
    r.handshake_confirmed = true
    report("start", r)

    send(r, 0, 8, 0)
    report("sent 8", r)
    let first = recovery.on_ack(r, Application, [recovery.AckRange { smallest: 0, largest: 7 }], 0, 40 * ms)?
    print("acked {first.acked.len}, lost {first.lost.len}, rtt sample {first.rtt_updated}")
    report("after ack", r)

    send(r, 8, 6, 50 * ms)
    let second = recovery.on_ack(r, Application, [recovery.AckRange { smallest: 12, largest: 13 }], 0, 90 * ms)?
    print("acked {second.acked.len}, lost {second.lost.len}")
    for p in second.lost {
        print("lost packet {p.number}")
    }
    report("after loss", r)
    print("slow start over: {r.ssthresh == r.congestion_window}")
    print("can send 1200: {recovery.can_send(r, 1200)}")
}

The loss detection and congestion control state of one connection path (RFC 9002).

The module reads no clock and performs no I/O: every time is a nanosecond reading supplied by the caller, and every timer is a value for the caller to wait for. Fields marked as set by the caller are read at the next event or rearm_timer call. A new value comes from recovery.

can_send

pub fn can_send(r: *Recovery, bytes: i64) -> bool

Returns whether sending bytes more bytes keeps the bytes in flight within the congestion window.

Probe packets sent after a timeout and the packet that follows entering recovery bypass the window; the caller decides when to ask.

closing_duration

pub fn closing_duration(r: *Recovery) -> i64

Returns three times pto_duration in nanoseconds, the length of the closing and draining periods.

deadline

pub fn deadline(r: *Recovery) -> i64

Returns the time at which the caller must call on_timeout, or -1 when no timer is armed.

The value is the time threshold loss time of the earliest space when one is waiting. Otherwise it is the probe timeout of the earliest space with an ack-eliciting packet in flight, which backs off by 2 for each pto_count. Initial and Handshake periods omit max_ack_delay, the Application space is never armed before handshake_confirmed, and a server with amplification_blocked has no timer. A client that has not completed address validation arms the timer even with nothing in flight, starting from the time of the last event.

The value only changes when an event or rearm_timer recomputes it. A value in the past means the timeout is due.

discard_space

pub fn discard_space(r: *Recovery, space: Space, now: i64)

Forgets every packet of space at time now, as when its keys are discarded.

The packets leave bytes_in_flight, the space's loss time and last ack-eliciting time are cleared, pto_count returns to 0 and the timer is recomputed. Call it for the Initial space when Handshake packets are first sent or received, and for the Handshake space when the handshake is confirmed.

on_ack

pub fn on_ack(r: *Recovery, space: Space, ranges: []AckRange, ack_delay_ns: i64, now: i64) -> AckResult ! io.Error

Processes an ACK frame received in space at time now and returns what it newly acknowledged and caused to be lost.

ranges are the acknowledged packet numbers in the descending order of the frame, and ack_delay_ns is the decoded acknowledgment delay in nanoseconds. Fails Malformed without changing any state when ranges is empty, when a range is reversed or negative, when ranges overlap or are not in descending order, when the frame acknowledges a number never sent, or when a range covers a number marked by skip. The caller answers with a PROTOCOL_VIOLATION connection error. Only the first 256 ranges are processed. Each range is located by binary search over the tracked packets, so the work is bounded by the number of ranges and the packets they newly acknowledge, never by the size of a range or by how many packets are outstanding. A number that was sent without being in flight, was acknowledged before or was declared lost is accepted and ignored.

The largest acknowledged number counts as a round-trip time sample when the frame newly acknowledges that packet, which must have been in flight, and at least one newly acknowledged packet is ack-eliciting. The sample is never negative and is capped at 2^40 ns. min_rtt takes the raw sample. The acknowledgment delay is ignored in the Initial space, capped by max_ack_delay once handshake_confirmed is set, never exceeds the sample and is not subtracted when that would put the sample below min_rtt.

It then declares lost the earlier packets that are three or more packet numbers or more than 9/8 of the round-trip time older than the largest acknowledged, applies the NewReno window rules to the losses and acknowledgments, and resets pto_count unless this is a client that has not completed address validation. An acknowledgment in the Handshake space sets peer_completed_address_validation. A frame that acknowledges no new packet and does not raise the largest acknowledged number changes nothing; one that raises it still runs loss detection, so an acknowledgment of a packet that was not in flight can declare earlier packets lost.

Persistent congestion is established when two ack-eliciting packets sent after the first round-trip time sample are declared lost together, no packet sent between them was acknowledged, and the span exceeds three probe timeout periods including max_ack_delay. It sets the window to the minimum, ends the recovery period and makes the next sample the new min_rtt.

on_sent

pub fn on_sent(r: *Recovery, space: Space, p: Sent)

Records that the packet p was sent in space.

A packet that is not in flight only raises the highest number sent, so an acknowledgment of it is accepted but reports nothing. An in-flight packet is tracked until it is acknowledged or declared lost, adds its size to bytes_in_flight, and, when ack-eliciting, becomes the last ack-eliciting packet of its space. The timer is recomputed at p.time. Numbers in one space must strictly increase and times must not decrease.

on_timeout

pub fn on_timeout(r: *Recovery, now: i64) -> Timeout

Handles the expiry of the loss detection timer at time now and returns what the caller must do.

Call it when now reaches deadline. When a space has a time threshold loss time, the packets that are now overdue are declared lost and returned in lost, the window rules apply, and no probe is requested. Otherwise it is a probe timeout: pto_count increases, which doubles the next period, and probe names the space whose ack-eliciting data the caller sends again, in probes datagrams. A probe timeout does not declare packets lost. When nothing is in flight at a client that has not completed address validation, probe is the Handshake space if has_handshake_keys is set and the Initial space otherwise, with one probe; the caller sends an ack-eliciting Handshake packet, or an Initial packet padded to 1200 bytes. Probe packets bypass can_send and are reported through on_sent.

Returns a Timeout with no loss and no probe when no timer is armed.

pto_duration

pub fn pto_duration(r: *Recovery) -> i64

Returns the probe timeout period in nanoseconds without backoff: the smoothed round-trip time, four times its variation (at least 1 ms) and max_ack_delay.

A connection that sends CONNECTION_CLOSE waits three times this period in the closing and draining states, which is closing_duration.

rearm_timer

pub fn rearm_timer(r: *Recovery, now: i64)

Recomputes the loss detection timer at time now.

Call it after changing handshake_confirmed, peer_completed_address_validation, has_handshake_keys or amplification_blocked, and when a server receives a datagram while amplification_blocked was set. Then compare deadline with now: a timer already in the past is due, so the caller runs on_timeout.

skip

pub fn skip(r: *Recovery, space: Space, number: i64)

Marks number as a packet number the sender deliberately leaves unused in space, the defence against optimistic acknowledgments (RFC 9000 section 21.4).

Call it for numbers above every number already sent, then continue numbering above it. on_ack fails Malformed for a frame that covers a skipped number. The most recent 32 skipped numbers per space are remembered. Packet threshold loss assumes consecutive numbers, so a skipped number makes a loss one packet later than otherwise. A number at or below the highest number sent is ignored.

recovery

pub fn recovery(max_datagram_size: i64) -> *Recovery

Returns the state of a new path whose datagrams carry at most max_datagram_size bytes of payload, which is at least 1200 for QUIC.

The round-trip time starts at 333 ms, the window at min(10 * size, max(14720, 2 * size)) bytes in slow start, and the minimum window at 2 * size. The packet threshold is 3, the time threshold 9/8 of the round-trip time, the timer granularity 1 ms, the loss reduction factor 1/2 and the persistent congestion threshold 3. A client starts without a validated address, so peer_completed_address_validation is false; a server sets it.
