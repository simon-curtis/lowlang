std/crypto/otp

#crypto

import std/crypto/otp

HOTP (RFC 4226) and TOTP (RFC 6238) over SHA-1, SHA-256 and SHA-512: hotp, totp, verify_totp with a window, verify_hotp, generate_secret, base32 secrets, and otpauth:// uri and parse_uri.

Imports std/base32, std/builder, std/crypto, std/crypto/hash, std/io, std/text, std/uri.

Examples

two_factor

import std/crypto/otp

fn describe(accepted: bool) -> str {
    if accepted { "accepted" } else { "rejected" }
}

fn run() ! otp.Error {
    let secret = bytes("12345678901234567890")
    let key = otp.Key { kind: otp.Kind.Totp, account: "ada@example.com", issuer: "Example Co", secret, digits: 8 }
    let enrolment = otp.uri(key)
    print(enrolment)

    let stored = otp.parse_uri(enrolment)?
    print("account {stored.account} at {stored.issuer}, {stored.digits} digits every {stored.period}s")
    print("secret {otp.secret_to_base32(stored.secret)}")

    let now = 1111111109
    let code = otp.totp(stored.secret, now, stored.period, stored.digits, stored.algorithm)?
    print("code at {now}: {code}")
    for drift in [0, 30, 60, -30, -60] {
        let accepted = otp.verify_totp(stored.secret, code, now + drift, stored.period, stored.digits, stored.algorithm, 1)?
        print("  {drift}s of clock drift: {describe(accepted)}")
    }

    let first = otp.hotp(stored.secret, 0, 6, otp.Algorithm.Sha1)?
    let third = otp.hotp(stored.secret, 2, 6, otp.Algorithm.Sha1)?
    print("hotp counters 0 and 2: {first} {third}")
    let next = otp.verify_hotp(stored.secret, third, 0, 5, 6, otp.Algorithm.Sha1)?
    print("counter stored after the third code: {next ?? -1}")
    let replay = otp.verify_hotp(stored.secret, third, next ?? 0, 5, 6, otp.Algorithm.Sha1)?
    print("replayed code: {describe(replay != none)}")
}

/// Enrols an authenticator with an `otpauth://` URI, then checks TOTP codes across clock drift and resynchronises an HOTP counter with a look-ahead window.
fn main() {
    run() catch {
        e => print("failed: {e}")
    }
}

uri

pub fn uri(key: Key) -> str

Returns the otpauth:// URI for key, suitable for a QR code.

The label is issuer:account (or the account alone when the issuer is empty), percent-encoded, followed by the secret (unpadded Base32), issuer, algorithm, digits and either period for a Totp key or counter for a Hotp key.

Functions

generate_secret

pub fn generate_secret(length: i64) -> []u8

Returns length random bytes from the system random source for use as a shared secret.

RFC 4226 recommends at least 16 bytes and 20 bytes for HMAC-SHA-1.

hotp

pub fn hotp(secret: []u8, counter: i64, digits: i64, algorithm: Algorithm) -> str ! Error

Returns the HOTP code (RFC 4226) for counter as a string of digits decimal digits.

The code is the dynamic truncation of HMAC(secret, counter), with the counter encoded as 8 big-endian bytes, reduced modulo 10^digits and left-padded with zeros. Fails with BadDigits when digits is not in 6..=8.

parse_uri

pub fn parse_uri(source: str) -> Key ! Error

Parses an otpauth:// URI into a Key.

The issuer is taken from the label prefix; the label separator may be : or its percent-encoded form. An issuer query parameter overrides the label prefix. Parameters other than secret, issuer, algorithm, digits, period and counter are ignored, and fields not given keep the defaults of Key.

Fails with BadUri when the scheme or type is not recognised, the percent-encoding is invalid or an hotp URI has no counter. Fails with BadSecret when secret is missing or not Base32, BadAlgorithm for an unknown algorithm, BadDigits when digits is not a number in 6..=8 and BadPeriod when period is not a positive number.

secret_from_base32

pub fn secret_from_base32(text: str) -> []u8 ! Error

Returns the bytes of the RFC 4648 Base32 text.

Spaces and hyphens are ignored so a secret grouped for reading decodes unchanged. Fails with BadSecret when the remaining text is not valid Base32.

secret_to_base32

pub fn secret_to_base32(secret: []u8) -> str

Returns secret as unpadded RFC 4648 Base32, the form authenticator apps expect.

totp

pub fn totp(secret: []u8, time: i64, period: i64, digits: i64, algorithm: Algorithm) -> str ! Error

Returns the TOTP code (RFC 6238) for the Unix time in seconds as a string of digits decimal digits.

The counter is time / period, so a code is valid for period seconds; authenticator apps use 30. Fails with BadPeriod when period is not positive, BadTime when time is negative and BadDigits when digits is not in 6..=8.

verify_hotp

pub fn verify_hotp(secret: []u8, code: str, counter: i64, window: i64, digits: i64, algorithm: Algorithm) -> i64? ! Error

Checks code against the HOTP codes for counter up to counter + window inclusive and returns the counter to store next, or none when no code matches.

The returned value is one past the matching counter, so a code cannot be accepted twice. Every counter in the window is computed regardless of where a match occurs, and each comparison is constant-time. Fails with BadDigits when digits is not in 6..=8.

verify_totp

pub fn verify_totp(secret: []u8, code: str, time: i64, period: i64, digits: i64, algorithm: Algorithm, window: i64) -> bool ! Error

Returns whether code is the TOTP code for any step from window steps before to window steps after the one containing time.

window counts steps of period seconds; 1 tolerates one step of clock drift either way and 0 accepts only the current step. Steps below zero are skipped. Every step is computed and each comparison is constant-time. Fails with BadPeriod, BadTime or BadDigits as totp does. The function does not remember used codes, so a caller that must reject replays records the accepted step itself.
