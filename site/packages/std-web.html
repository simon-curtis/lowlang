std/web

#web

import std/web

A router with groups, middleware and typed JSON endpoints, problem details (RFC 9457), an OpenAPI 3.1 document built from the types, cookie sessions, CSRF protection, API key, Basic and bearer authentication, CORS and response compression. static and static_with serve a directory. events and event_stream serve server-sent events.

Imports std/base64, std/crypto, std/crypto/aead, std/crypto/hash, std/crypto/jose, std/file, std/header, std/html, std/http, std/http/files, std/http/sse, std/io, std/json, std/otel, std/serde, std/slices, std/text, std/time, std/uri.

A router: routes, the middleware applied to them and a path prefix.

Made by app. group makes a child app that registers its routes on the same router.

endpoint

pub fn endpoint[Req, Res](a: *App, method: str, path: str, status: i64, handle: fn(*Context, Req) -> Res ! Problem) -> *Operation

Registers a route whose handler takes a JSON body decoded as Req and returns a Res as JSON.

The response has status on success. A body that does not decode, or a Problem that handle fails with, becomes the problem response. The schemas of Req and Res and status are recorded in the returned Operation for the OpenAPI document.

group

pub fn group(a: *App, prefix: str, middleware: []Middleware) -> *App

Returns a child app whose routes carry prefix appended to the parent's prefix and the parent's middleware followed by middleware.

The child registers its routes on the parent's router, in the order of registration across both.

handler

pub fn handler(a: *App) -> fn(http.Request) -> http.Response

Returns the app as a request handler for http.serve.

A request whose path matches a route of another method runs the middleware of the first such route and then gets a 405 problem with an allow header, so middleware such as cors can answer first. A request that matches no route gets a 404 problem. Each request is recorded as a server span named after the matched route pattern.

oidc_login

pub fn oidc_login(a: *App, login: str, callback: str, client: OidcClient, signed_in: fn(*Context, jose.Claims) -> http.Response)

Registers the two routes of an authorization-code sign-in with PKCE on a.

login redirects with 302 to the provider's authorization endpoint with a fresh state, nonce and code challenge, which it keeps in the session, and answers 502 when the provider cannot be reached. callback checks state, exchanges the code, verifies the ID token and its nonce, clears the stored values, and returns the response of signed_in called with the verified claims. A bad state or missing code gets a 400 problem, and a failed exchange or nonce mismatch a 401 problem. The sessions middleware must wrap both routes, and a request that reaches either route without it gets a 500 problem.

openapi

pub fn openapi(a: *App, path: str, info: Info)

Registers a GET route at path that serves the document of openapi_document as JSON.

The document is built on each request, so it reflects the routes registered at that time.

openapi_document

pub fn openapi_document(a: *App, info: Info) -> json.Value

Returns an OpenAPI 3.1 document for the routes of the app.

A :name segment becomes {name} with a path parameter. Operations list their summary, description, tags, request body and response from their Operation, a default response of the Problem schema, and the security schemes of their middleware. Struct and enum schemas are shared in components.schemas.

route

pub fn route(a: *App, method: str, path: str, handler: fn(*Context) -> http.Response) -> *Operation

Registers a handler for method and path and returns the route's Operation.

The app's prefix is prepended to path. A segment starting with : captures one path segment into Context.params, and a final * segment captures the rest of the path under "*". Routes are tried in registration order, and the first whose path and method match handles the request. A GET route also answers HEAD.

static

pub fn static(a: *App, prefix: str, dir: str)

Serves the files under dir below prefix with the default options. See static_with.

static_with

pub fn static_with(a: *App, prefix: str, dir: str, o: StaticOptions)

Serves the files under dir for GET requests below prefix.

The request path must not contain .., a backslash or an encoded slash, or the response is a 400 problem. A path that resolves outside dir, including through a symbolic link, or to anything but a regular file or directory, gets a 404 problem. A directory requested without a trailing slash is redirected with 301. Files are served by files.serve_file_with, so HEAD, conditional and range requests are supported.

use

pub fn use(a: *App, m: Middleware)

Adds a middleware to the app.

It applies only to routes registered after this call, so call it before registering the routes it should wrap.

event_stream

pub fn event_stream(c: *Context, producer: fn(*sse.Emitter)) -> http.Response

Returns a Server-Sent Events response fed by producer.

producer runs in its own task with an emitter, and the stream ends when it returns. sse.send on the emitter returns false once the client has disconnected.

events

Returns a Server-Sent Events response that sends every event received on ch.

The stream ends when ch is closed or the client disconnects. A keepalive comment is sent when no event has arrived for the default keepalive interval.

sessions

pub fn sessions(o: SessionOptions) -> Middleware ! io.Error

Returns a middleware that keeps a Session for each visitor in an encrypted cookie.

Fails with Invalid when o.key is not 32 bytes. The cookie holds the values and an expiry, sealed with AES-256-GCM and bound to the cookie name. A cookie that is missing, altered or expired gives an empty session. A cookie is sent only when the request changed the session, which restarts its lifetime, or cleared it, which deletes the cookie. A session that is cleared stays cleared even if values are set afterwards. The scheme is listed in the OpenAPI document as an apiKey in a cookie.

Functions

api_key

pub fn api_key(header_name: str, check: fn(str) -> str?) -> Middleware

Returns a middleware that authenticates requests by the API key in the header_name header.

check maps a key to the principal it belongs to, or none to reject it. A principal is stored in Context.user. A missing, empty or rejected key gets a 401 problem. The scheme is listed in the OpenAPI document as an apiKey in a header.

app

pub fn app() -> *App

Returns an empty app with no routes, no middleware and no prefix.

basic

pub fn basic(realm: str, check: fn(str, str) -> str?) -> Middleware

Returns a middleware that authenticates requests with HTTP Basic credentials.

check receives the user name and password and returns the principal, which is stored in Context.user, or none to reject them. The user name ends at the first colon of the decoded credentials. Missing, malformed or rejected credentials get a 401 problem with a www-authenticate: Basic challenge for realm.

bearer

pub fn bearer(check: fn(str) -> json.Value?) -> Middleware

Returns a middleware that authenticates requests with a bearer token from the authorization header.

check returns the token's claims, or none to reject it. Accepted claims are stored in Context.claims, and a string sub claim is stored in Context.user. A missing or rejected token gets a 401 problem. The scheme is listed in the OpenAPI document as HTTP bearer with the JWT format.

compress

pub fn compress(minimum: i64, level: i64) -> Middleware

Returns a middleware that compresses response bodies.

The coding is the first of zstd, br and gzip that the accept-encoding header accepts with a non-zero quality. A response is compressed only when its body has at least minimum bytes, is not streamed, has no content-encoding, and has a content-type that is text/* other than an event stream, or contains json, xml, javascript or svg. level is passed to the compressor. The response gets content-encoding and vary: Accept-Encoding, replacing any vary it had, and loses its content-length.

cors

pub fn cors(origin: str, allow_headers: []str) -> Middleware

Returns a middleware that allows cross-origin requests from origin with the request headers allow_headers.

It sets access-control-allow-origin and vary: Origin on every response. A request with method OPTIONS is answered with 204, the allowed methods and allow_headers joined by commas, without calling the rest of the chain. The middleware runs for a request whose path matches a route of another method, so a preflight for a route registered with get or post reaches it.

csrf

pub fn csrf() -> Middleware

Returns a middleware that rejects unsafe requests without the session's CSRF token.

Requests other than GET, HEAD and OPTIONS must carry an x-csrf-token header equal to the session's token, compared in constant time. Otherwise the response is a 403 problem. It must run after sessions.

pub fn jwt(keys: []jose.Jwk, options: jose.Options) -> Middleware

Returns a bearer middleware that accepts JWTs verified against keys under options.

The signature, exp, nbf, and the issuer and audience when options names them, are checked. The full payload becomes Context.claims. Any verification failure gets a 401 problem.

oidc

pub fn oidc(issuer: str, audience: str) -> Middleware

Returns a bearer middleware that accepts JWTs issued by the OpenID Connect provider at issuer for audience.

The signing keys come from the jwks_uri of the provider's discovery document. They are cached for an hour and refetched when a token names an unknown kid, at most once a minute. Only asymmetric signature algorithms are accepted. A token that fails verification, or a provider that cannot be reached, gets a 401 problem. The scheme is listed in the OpenAPI document as openIdConnect.
