std/http/sse

#net #web

import std/http/sse

Server-sent events. Shared: Event (id, event, data, retry), format, comment and keepalive. Server: stream, stream_with, serve_events, serve_events_with, Emitter and last_event_id. Client: parser, feed, parse and listen, which reads a text/event-stream response with any chunking and CR, LF or CRLF line ends.

Imports std/cancel, std/header, std/http, std/io, std/text.

Examples

progress_feed

import std/http
import std/http/sse
import std/io
import std/net
import std/text

fn steps(em: *sse.Emitter, from: i64) {
    let last = if from + 2 < 5 { from + 2 } else { 5 }
    for i in from..last + 1 {
        let sent = sse.send(em, sse.Event { id: some("{i}"), event: some("progress"), data: "step {i} of 5" })
        if !sent {
            return
        }
    }
}

fn handle(req: http.Request) -> http.Response {
    let resume = sse.last_event_id(req) ?? "0"
    let next = text.parse_uint(resume, 10) or 0
    sse.stream(req, fn(em: *sse.Emitter) { steps(em, next + 1) })
}

fn show(e: sse.Event) ! io.Error {
    print("{e.event ?? "message"} #{e.id ?? "-"}: {e.data}")
}

/// Streams progress events from a loopback server, then reconnects with `last-event-id` to resume.
fn main() ! io.Error {
    using l = net.listen("127.0.0.1", 0)?
    let listening = l.handle
    spawn fn() { http.serve_on(listening, handle) or {} }()
    let client = http.client().with_timeout(5000).build()
    let url = "http://127.0.0.1:{l.handle.addr.port}/progress"

    let first = sse.listen(client.request("GET", url), show) or return
    print("first stream: {first.status} {http.header_value(first, "content-type") ?? "-"}")

    let resumed = client.request("GET", url).with_header("last-event-id", "3")
    let second = sse.listen(resumed, show) or return
    print("resumed stream: {second.status}")
    net.close_listener(l)
}

The handle a producer uses to send events to the client.

The events go to the response created by stream or stream_with.

send

pub fn send(em: *Emitter, e: Event) -> bool

Sends e to the client and returns true, or returns false when the request has been cancelled.

Blocks while the response is not keeping up. A false result means the client is gone and the producer should return.

A server-sent event.

format writes it to the wire and parse and feed read it back.

format

pub fn format(e: Event) -> str

Returns the wire text of e: its id, event, retry and data fields in that order, each ending in a newline, followed by a blank line.

An event with empty data and no name has no fields and is only the blank line, which clients ignore. An empty-data event with a name writes an empty data field so that it is dispatched.

Parser

pub struct Parser {The reconnection delay in milliseconds from the latest valid retry field the parser has seen, or -1 when the stream has sent none.    pub reconnect: i64
    ...
}

An incremental parser for a text/event-stream body.

It follows the WHATWG event stream rules: lines end in \n, \r or \r\n, a leading byte order mark is skipped, lines beginning with : are comments, unknown fields are ignored, and a blank line dispatches the event. A Parser keeps partial lines and a partial event between calls to feed, so chunks may be split anywhere.

feed

pub fn feed(p: *Parser, chunk: []u8) -> []Event

Parses chunk and returns the events it completes, in order.

An event is returned when its terminating blank line is read, and only if it had at least one data field. Multiple data lines are joined with \n. Event.id is the latest id the stream set, which carries over to later events and is none when that id was empty, Event.event is the event field if one was given, and Event.retry is set only on the event that followed a retry field. An id containing a zero byte is ignored, and so is a retry that is not all digits. Input after the last line ending stays in the parser until more arrives.

Functions

comment

pub fn comment(note: str) -> str

Returns note as an event stream comment: one line beginning with : for each line of note, followed by a blank line.

Clients ignore comments.

keepalive

pub fn keepalive() -> str

Returns the comment that keeps an idle stream open.

last_event_id

pub fn last_event_id(req: http.Request) -> str?

Returns the last-event-id header of req, which a reconnecting client sends to resume, or none when it is missing or empty.

listen

pub fn listen(b: http.Builder[http.Response], on_event: fn(Event) ! io.Error) -> http.Response ! http.Error

Sends the request built by b and calls on_event for each event of the response as it arrives, until the stream ends.

The request gets accept: text/event-stream and cache-control: no-cache. Returns the response, whose body is empty because it was delivered to on_event. Failures are those of stream_to; an error from on_event stops reading and is returned as Io. It does not reconnect or send last-event-id.

serve_events_with

pub fn serve_events_with(req: http.Request, o: Options, events: chan[Event]) -> http.Response

Returns a streaming 200 response that writes each event received from events in the text/event-stream format.

The response has content-type: text/event-stream, cache-control: no-cache and x-accel-buffering: no. If o.retry is not negative it is sent first, and after o.keepalive milliseconds without an event a keepalive comment is sent. The stream ends when the caller closes events or the request is cancelled. Nothing reads events after cancellation, so a sender should watch req.token.

stream

pub fn stream(req: http.Request, producer: fn(*Emitter)) -> http.Response

Returns the response of stream_with with the default Options.

stream_with

pub fn stream_with(req: http.Request, o: Options, producer: fn(*Emitter)) -> http.Response

Returns a streaming response that runs producer on a new task and sends the events it passes to send.

The stream ends when producer returns. The producer should stop when send returns false.
