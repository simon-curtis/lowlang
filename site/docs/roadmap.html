Roadmap

The roadmap is the issues labelled roadmap on GitHub, with each item's sub-issues nested beneath it.

  1. Standard library, written in Low

    The standard library modules still to write, in Low.

    1. Vector values in registers across blocks and calls, and AVX-512

      Vector values in registers across blocks and calls, and an AVX-512 version.

    2. QUIC and HTTP/3

      QUIC (RFC 9000, 9001 and 9002) over UDP with the TLS 1.3 handshake, loss recovery and congestion control; HTTP/3 (RFC 9114) with QPACK (RFC 9204).

    3. WebRTC data channels and SRTP media

      WebRTC data channels: ICE with STUN, DTLS, SCTP over DTLS and the data channel establishment protocol; media over SRTP.

    4. Cryptography

      Cryptographic primitives and protocols for std/crypto and std/tls.

      1. CSPRNG: ChaCha20 for crypto.random and AES-256-CTR-DRBG

        Random generation: a ChaCha20 CSPRNG seeded from getrandom for crypto.random, and AES-256-CTR-DRBG (NIST SP 800-90A).

      2. Post-quantum signatures: ML-DSA, SLH-DSA and Falcon

        Post-quantum signatures: ML-DSA-44, ML-DSA-65 and ML-DSA-87 (FIPS 204), SLH-DSA (FIPS 205), and Falcon (FN-DSA).

      3. HPKE (RFC 9180)

        HPKE (RFC 9180) with the DHKEM(X25519) and X25519MLKEM768 KEMs, HKDF-SHA-256 and the AES-256-GCM and ChaCha20-Poly1305 AEADs.

      4. Shamir's secret sharing

        Shamir's secret sharing over GF(2^8).

      5. VOPRF (RFC 9497)

        VOPRF (RFC 9497) over ristretto255 and P-256.

      6. Zero-knowledge proofs: Groth16, Halo2 and STARKs

        Zero-knowledge proofs: Groth16 over BN254 and BLS12-381, Halo2 with KZG and IPA commitments, and STARKs over FRI.

      7. Homomorphic encryption: BFV, CKKS and TFHE

        Homomorphic encryption: BFV, CKKS and TFHE.

      8. Certificate status: OCSP, CRLs and OCSP stapling

        Certificate status: OCSP (RFC 6960) and CRL checks in std/crypto/x509 chain validation, and OCSP stapling in std/tls.

      9. ACME (RFC 8555) client

        ACME (RFC 8555): account keys, orders, HTTP-01 and TLS-ALPN-01 challenges, and renewal before expiry, feeding certificates to std/tls servers.

    5. DNS: search domains, TCP fallback and record lookups

      DNS: search domains and ndots from /etc/resolv.conf, TCP fallback on truncated replies, CNAME chasing, and MX, TXT, SRV, CAA and PTR lookups over a message encoder and decoder.

    6. IDNA, Punycode and the public suffix list

      Hostnames: IDNA (UTS #46) with Punycode (RFC 3492), and an embedded public suffix list that the HTTP client's cookie jar checks domains against.

    7. gRPC clients and servers

      gRPC: unary and streaming clients and servers over the HTTP/2 stack with status codes, deadlines, metadata and compression; std/otel exports through it.

    8. std/protobuf: serde and a .proto parser

      std/protobuf: serialize[T] and deserialize[T] through serde, and a .proto parser that generates Low types.

    9. Database drivers: MySQL, MariaDB and MongoDB

      Database drivers: MySQL and MariaDB over the client/server protocol, plain or over TLS; MongoDB over OP_MSG with std/bson.

    10. Messaging clients: MQTT, AMQP, Kafka and NATS

      Messaging clients: MQTT 3.1.1 and 5, AMQP 0-9-1, Kafka and NATS.

    11. SSH and SFTP

      SSH: the transport (RFC 4253), user authentication with keys and passwords, the connection protocol with sessions and port forwarding, clients and servers, and SFTP.

    12. D-Bus

      D-Bus: the wire format over Unix sockets, the session and system buses, method calls, signals and properties.

    13. syslog, journald and SNTP

      System logging and time: syslog (RFC 5424) and the journald native protocol as std/log destinations; an SNTP client (RFC 4330).

    14. std/html: tree builder, selectors and sanitizer

      std/html: a WHATWG tree builder, CSS selector queries and an allow-list sanitizer.

    15. Markdown rendering

      Markdown: CommonMark with GitHub tables, task lists, strikethrough and autolinks, rendered to HTML.

    16. Avro, Parquet and Arrow IPC

      Columnar and row formats: Avro with schema resolution and object container files; Parquet and Arrow IPC readers and writers.

    17. std/unicode: segmentation and line breaking

      std/unicode: grapheme cluster, word and sentence segmentation (UAX #29) and line breaking (UAX #14) from embedded Unicode tables.

    18. Locales: CLDR plurals, formatting and collation

      Locales: CLDR plural rules, number, currency, date and time formatting, and collation (UTS #10); std/time/humanize and std/text/number take a locale.

    19. Numerics: statistics, complex numbers, matrices and FFT

      Numerics: statistics (mean, median, variance, standard deviation, percentiles, histograms), complex numbers, dense matrices with LU and QR decomposition and linear solves, and FFT.

    20. Memory-mapped files, user lookup, rlimits and cgroup limits

      std/file memory-mapped files with msync and madvise; std/os user and group lookup, getrlimit and setrlimit, and cgroup v2 CPU and memory limits.

  2. GPU UI library

    GPU UI library with GPUI's renderer and platform layer and a signal-based state model, Linux first.

    1. Wayland window and Vulkan swapchain

      A Wayland window through libwayland-client, with bindings generated from protocol XML; a Vulkan swapchain through VK_KHR_wayland_surface; a clear colour.

    2. GPU scene primitives and shaders

      A scene of GPU primitives (shadows, quads with rounded corners and borders, paths, underlines, monochrome, subpixel and polychrome sprites) drawn by GLSL shaders compiled to embedded SPIR-V. Primitives are sorted by draw order, batched by kind and atlas texture, and clipped by content masks.

    3. Text: fonts, glyph atlas, shaping and line layout

      Text: font discovery with an embedded fallback font, OpenType parsing, rasterizing into a glyph atlas, shaping, and line layout over std/unicode segmentation.

    4. Retained element tree

      A retained element tree. Components run once at mount and build elements; only the closures that read a signal run again.

    5. Signals, memos and effects

      Signal[T], Memo[T: Eq] and effects. Reads are tracked through a current-observer scope on the UI thread. A memo whose new value is equal to the old one does not propagate.

    6. Dynamic branches and keyed lists

      Reactive structure through explicit containers: a dynamic branch, and a keyed dynamic list.

    7. Incremental layout

      Incremental layout: a flexbox subset with dirty flags that propagate to ancestors and cached measurements, so a change re-lays out only the affected subtrees.

    8. Incremental paint

      Incremental paint: per-element scene fragments are reused, and only dirty elements re-emit primitives.

    9. Styles with hover and active overrides

      Styles with partial overrides for hover and active states, driven by signals.

    10. Input: keyboard, mouse, focus and keymaps

      Input: libxkbcommon keyboard, key repeat, hitboxes, mouse dispatch, focus and tab stops, actions and keymaps. Focus and hover state are signals.

    11. Foreground and background executors

      Foreground and background executors on the scheduler; a background task's result is written into a signal on the UI thread.

    12. Text input, clipboard, IME and window decorations

      Text input element whose state is held in signals, clipboard, IME (text-input-v3), fractional scale, cursor-shape, xdg-decoration and client-side decorations.

    13. Portals, AT-SPI, PNG images and SVG paths

      Portals and AT-SPI over D-Bus, PNG images, SVG paths.

  3. wasm32 target and browser playground

    A wasm32 target and a browser playground that runs snippets.

    1. Targets named by OS and architecture

      Targets named by OS and architecture, with wasm32 beside amd64.

    2. WebAssembly back end

      A WebAssembly back end lowered from the IR: structured control flow rebuilt from the IR's blocks, locals in place of registers, a linear-memory heap with the size-class bins, and a module written directly without an external assembler or linker.

    3. Browser host

      A browser host: print and the clock as JavaScript imports; modules that need the OS (files, sockets, processes, the UI library) are rejected at compile time for this target.

    4. Compiler built for js/wasm

      The compiler built for js/wasm, so the page compiles and runs a snippet without a server.

    5. Run buttons and a playground page

      A Run button on every documentation snippet, and an editable playground page on the site.

  4. Standard library and tools on Windows

    The standard library and the low tools on Windows.

    1. OS-specific std code selected by target Done

      OS-specific std code selected by target, so each OS-facing module (std/os, std/os/signal, std/file, std/net, std/process) carries one implementation per OS behind one API.

    2. Reject __syscall on the Windows target

      __syscall rejected at compile time on the Windows target, so a module without a Windows implementation fails the build.

    3. std/process on Windows

      std/process over kernel32: CreateProcessW with Windows command-line quoting, CreatePipe with overlapped reads and writes for piped streams, WaitForSingleObject and GetExitCodeProcess, TerminateProcess, job objects for process groups, and find over PATH and PATHEXT.

    4. low dev on a Windows host

      low dev on a Windows host.

  5. Package registry

    A package registry for Low modules.

    1. low.mod, low.sum and the module cache

      Dependencies declared in low.mod with a version each, a low.sum lockfile holding exact versions and content hashes, and a module cache that imports resolve to.

    2. Publishing from tagged git repositories

      Packages published from tagged git repositories, each version immutable once indexed, and yanking in place of deletion.

    3. Package pages on the website

      A package page on the website for every indexed version, generated with low doc as the standard library pages are.
