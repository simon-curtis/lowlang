UI

std/ui draws a window's user interface with Vulkan, on Wayland on Linux and on Win32 on Windows. A program builds a tree of elements from its state; the library lays it out, paints it, draws it and dispatches input to it. Below it sit modules for windows and input, a flexbox layout engine, fonts and text, a scene of GPU primitives, and a renderer that draws a scene into an offscreen target or a window.

Generators

  • internal/wlgen/protocols holds the Wayland protocol XML: wayland.xml, xdg-shell.xml, cursor-shape-v1.xml, xdg-decoration-unstable-v1.xml, text-input-unstable-v3.xml, fractional-scale-v1.xml and viewporter.xml from wayland-protocols 1.45. go run ./cmd/wlgen -o internal/compiler/std/ui/platform/wayland_linux.low internal/wlgen/protocols/wayland.xml internal/wlgen/protocols/xdg-shell.xml internal/wlgen/protocols/cursor-shape-v1.xml internal/wlgen/protocols/xdg-decoration-unstable-v1.xml internal/wlgen/protocols/text-input-unstable-v3.xml internal/wlgen/protocols/fractional-scale-v1.xml internal/wlgen/protocols/viewporter.xml generates the Wayland bindings. A new_id argument must create an interface one of the given protocols declares; an object argument of an interface none declares, such as zwp_tablet_tool_v2, gets a null type entry, which libwayland does not check.
    • Every interface given in one run shares an Interfaces record of wl_interface tables that interfaces() builds in C memory. The record keeps every block it allocates, listener copies included, and release_interfaces(ifs) frees them once the connection is closed. A reference to an interface that no given protocol declares is an error.
    • A request becomes interface_request(...) over wl_proxy_marshal_flags, taking the Interfaces record when it creates an object of a known interface. wl_registry_bind takes the interface table and version.
    • Destructor requests pass WL_MARSHAL_FLAG_DESTROY, and an interface without a destroy request gets one that calls wl_proxy_destroy.
    • Objects are ptr, strings ptr[u8], fixed an i32.
    • Events become an extern struct listener of extern fn fields, each defaulting to a generated function that ignores the event, so a listener names only the events it handles. interface_add_listener(ifs, proxy, listener, data) copies it into the record's C memory. Callbacks receive the listener's data pointer, a pinned Low object.
    • Enum entries are functions such as wl_shm_format_argb8888() -> u32. Names that clash with Low keywords or builtins gain a trailing _.
  • internal/vkgen/registry holds the Vulkan registry, vk.xml.gz from Vulkan-Docs v1.4.363, and vulkan.list, which selects extensions, commands, extra types such as pNext structures, and the library each target loads.
    • go run ./cmd/vkgen -registry internal/vkgen/registry/vk.xml.gz -select internal/vkgen/registry/vulkan.list -o internal/compiler/std/ui/gpu writes vulkan.low and one vulkan_<os>.low per target. A command line that ends with a target name, such as command vkCreateWaylandSurfaceKHR linux, goes only to that target's file, and library windows vulkan-1 names the library its extern block links.
    • Commands and every type they reach are generated, skipping Vulkan SC variants. Enum values come from the core enums, every Vulkan feature level and the selected extensions.
    • A handle is a one-field extern struct, ptr for dispatchable handles and i64 for the others, so VkBuffer {} is the null handle and handles of different kinds do not mix.
    • Structures and unions become extern structs whose fields all have defaults: zero, null, the empty handle, or for sType the structure's own value, so a literal names only what it sets. A union takes the layout of its widest member.
    • A fixed C array becomes numbered fields, name_0 to name_N, with an accessor Struct_name(s) that returns them as a slice, or as a str for a character array.
    • Vulkan types map to u32 (uint32_t, VkBool32, VkFlags, 32-bit flag bits), i32 (int32_t, enums), i64 (uint64_t, VkDeviceSize, VkFlags64, size_t), u16, u8, f32 and f64. Platform types such as HWND and wl_display* are ptr.
    • Pointers to known types become ptr[T]; void*, function pointers and pointers to pointers become ptr. A command's single input or output through a pointer is a mut parameter; an array or optional pointer is a ptr[T].
    • Enum entries and API constants are functions such as VK_FORMAT_R8G8B8A8_UNORM() -> i32, and vk_make_api_version builds version numbers.
  • Both generators emit declarations without pub. internal/vkgen and internal/wlgen fail when the checked-in files differ from what the generators produce.
  • std/ui/gpu/shaders holds the GLSL and its SPIR-V. go run ./cmd/shadergen internal/compiler/std/ui/gpu/shaders compiles each stage with glslc to a .spv and records the SHA-256 sums of the sources and the .spv files in shaders.sum.

Platform

std/ui/platform gives both targets one API:

  • open(Options) -> Window ! Error creates a window of a logical size with a title, asking for the Decorations it names. Window is droppable; releasing it destroys the window and closes the connection. A window belongs to the green thread that opened it.
  • next(w, timeout_ms) -> []Event ! Error returns the events that arrived, waiting until at least one arrives, a Waker fires or the timeout passes. A negative timeout waits without limit. The first next after open returns a Resized.
  • waker(w) -> Waker is a copyable handle; wake(k) makes the waiting next, or the next one, return a Woken. Each wake gives one Woken.
  • clipboard(w) -> Clipboard is a copyable handle to the system clipboard through the window. write_clipboard(c, text) ! Error puts text on it for other programs to paste, and read_clipboard(c) -> str? ! Error returns its text, none when it holds none. Both fail with Disconnected once the window is released.
  • open_url(url) ! Error opens a URL in the application the desktop registers for its scheme, such as the web browser for https, and returns without waiting for it. It refuses with Unsupported a string that fails is_url(s) -> bool, which asks for a scheme of at least two characters, a letter then letters, digits, +, - or ., and a colon, so a path, a drive letter or an option never reaches the launcher. Any scheme passes, file among them, so a URL from an untrusted source needs its scheme checked by the caller.
  • set_text_input(w, caret) turns text input through the system's input method on with a Caret, the logical rectangle the input method places its candidate window beside, or off with none. It starts off. While it is on, an input method can take keys and give Preedit(text, cursor) for the composition in progress, with its cursor as a TextRange of byte offsets into text or none when hidden, and empty text when the composition ends, and Commit(text) for text that replaces the composition. Setting the same caret again does nothing.
  • decorations(w) -> Decorations is Server while the windowing system draws the title bar and borders and Client while the program must, and status(w) -> WindowStatus says whether the window is maximized, fullscreen or tiled against a screen edge or another window. DecorationsChanged(d) and StatusChanged(s) report changes.
  • controls(w) -> Controls is a copyable handle for a window that draws its own title bar. start_move(c) and start_resize(c, edge) hand a button press that has not been released to the windowing system, which moves the window or resizes it from a ResizeEdge, and show_window_menu(c, x, y) shows the system's menu for the window at a logical position; without such a press they do nothing. set_maximized(c, on), set_fullscreen(c, on) and minimize(c) ask for those states, which StatusChanged confirms, and set_title(c, title) sets the title. They do nothing once the window is released.
  • set_cursor(w, cursor) shows a Cursor while the pointer is over the window: Arrow, Text, VerticalText, Pointer, Crosshair, Grab, Grabbing, NotAllowed, Copy, Alias, ContextMenu, Move, Wait, Progress, Help, the edge and axis resizes ResizeLeft, ResizeRight, ResizeUp, ResizeDown, ResizeLeftRight, ResizeUpDown, the diagonals ResizeUpLeftDownRight and ResizeUpRightDownLeft, ResizeColumn, ResizeRow, and Hidden. Setting the cursor already shown does nothing.
  • native(w) -> Native gives the handles Vulkan needs to make a surface: the wl_display and wl_surface on Linux, the HINSTANCE and HWND on Windows.
  • Error is NoDisplay(detail) when there is no compositor or no desktop, Unsupported(detail) when the windowing system lacks something the window needs, Failed(call, code) with the call's error code, and Disconnected.
  • Event is Resized(width, height, scale) in logical pixels and device pixels per logical pixel, all f32, CloseRequested, PointerMoved(x, y), PointerLeft, PointerDown(button, x, y), PointerUp(button, x, y), Scrolled(dx, dy), Key(KeyEvent), ModifiersChanged(Modifiers), Preedit(text, cursor), Commit(text), DecorationsChanged(Decorations), StatusChanged(WindowStatus), FocusChanged(bool) and Woken. Pointer positions are logical pixels from the top left of the window.
  • A KeyEvent carries a Key (Named(NamedKey) for Enter, Escape, Tab, Backspace, Delete, the arrows, Home, End, Page Up, Page Down and F1 to F12, or Character(str), the key's text with at most Shift applied), the text it produces with the modifiers held, the Modifiers (shift, control, alt, super), whether it is a press or a release, and whether it repeats. Control+A is Character("a") with empty text. Modifier keys, and keys with neither a name nor text, give no Key event; a change in the modifiers held gives ModifiersChanged, including on gaining focus with modifiers held.
  • The scale may be fractional: the Wayland fractional scale, else the surface's preferred buffer scale, or the window's DPI divided by 96 on Windows. The drawing surface is the logical size times the scale, each rounded to the nearest whole device pixel.
  • A Gpu made with gpu.open_for draws into the window, so it is released before the Window.

Wayland:

  • open connects to the display, binds wl_compositor, xdg_wm_base and wl_seat from the registry, and makes a surface with an xdg_toplevel. It returns once the first configure has been acknowledged, failing with Unsupported when none arrives within five seconds. When the compositor offers zxdg_decoration_manager_v1, the window asks for the decorations its options name; without it the decorations are Client.
  • Listener callbacks run during wl_display_dispatch_pending on the green thread that called next and append to the window's event queue, a pinned Low object. A failure inside a callback is kept and returned by the next next.
  • xdg_wm_base.ping is answered inside the callback, xdg_toplevel.close becomes CloseRequested, and a configure with a non-zero size becomes Resized. When the compositor offers wp_fractional_scale_manager_v1 and wp_viewporter, the surface gets a wp_viewport whose destination is the logical size, the buffer scale stays 1, and wp_fractional_scale_v1.preferred_scale in 120ths sets the scale. Otherwise wl_surface.preferred_buffer_scale sets a whole scale and the buffer scale follows it.
  • The keymap arrives as a file descriptor, which is read with std/sys and compiled with xkb_keymap_new_from_string. Keys are translated with xkb_state_key_get_one_sym and xkb_state_key_get_utf8, and modifiers follow xkb_state_update_mask on wl_keyboard.modifiers, which gives ModifiersChanged when the effective Shift, Control, Mod1 or Mod4 changed. libxkbcommon is bound by hand in xkb_linux.low.
  • When the compositor offers wp_cursor_shape_manager_v1, the cursor is set with wp_cursor_shape_device_v1.set_shape on each wl_pointer.enter and on each change while the pointer is inside, Arrow as default; without it only Hidden takes effect. Hidden sets a null cursor surface.
  • The clipboard is the wl_data_device selection of the seat, from wl_data_device_manager at version 3 or below. Writing offers a wl_data_source as text/plain;charset=utf-8, UTF8_STRING, text/plain, TEXT and STRING with the serial of the window's last button press, key press or keyboard enter, and answers each send by writing the text to the given descriptor. A compositor ignores a selection whose serial is not from recent input. While the window's source is the selection, reading returns its text without a round trip. Otherwise reading asks the selection's offer for its best text type through a pipe and reads it for up to one second. Without a data device manager writing fails with Unsupported and reading returns none.
  • open_url runs xdg-open with the URL as its argument through sh -c 'xdg-open "$1" &', with the standard streams on /dev/null, and reaps the shell, which returns at once; the init process reaps xdg-open when it ends. Without xdg-open on PATH it fails with Unsupported, and a shell that does not exit with 0 fails with Failed("sh", code).
  • Text input uses zwp_text_input_v3 from zwp_text_input_manager_v3 when the compositor offers it. It is enabled with a normal content type and the caret as the cursor rectangle while the window has text-input focus and a caret, and disabled when the caret is none; each change ends with a commit. preedit_string and commit_string are held until done, which gives Commit for non-empty commit text, then Preedit when the composition is or was non-empty. Leaving text-input focus ends a composition with an empty Preedit. Surrounding text is not sent, and delete_surrounding_text is ignored.
  • zxdg_toplevel_decoration_v1.configure sets the decorations. The states of xdg_toplevel.configure give the status, applied with the configure: maximized, fullscreen, and any of the four tiled_* states for tiled. start_move, start_resize and show_window_menu send xdg_toplevel.move, resize and show_window_menu with the seat and the serial of the window's last button press; the others send set_maximized, unset_maximized, set_fullscreen without an output, unset_fullscreen, set_minimized and set_title. Each flushes at once.
  • Key repeat follows the compositor's repeat_info: a held key that produces text or is a named key repeats from a timer inside next.
  • next waits on the display's file descriptor without blocking an OS thread. A green thread started by open waits with wait_readable(fd) each time next arms it and reports readiness on a channel; next prepares the read, then selects on that channel, the waker's channel and an after arm for the timeout, the next key repeat or 60 seconds, cancelling the read when anything else wins. Only one green thread may wait on a descriptor, so a flush that would block retries every millisecond for up to five seconds.
  • A broken or reset connection gives Disconnected. The generated bindings' C memory is freed when the window is released.

Win32:

  • open locks the green thread to its OS thread with sync.lock_thread, because a window's messages reach only the thread that created it. It sets per-monitor DPI awareness, registers the LowWindow class once per process, and creates the window with CreateWindowExW, its title converted to UTF-16. A creation error of 0 or access denied gives NoDisplay.
  • The window procedure is a Low callback. It reaches the window's state through GWLP_USERDATA, set from lpCreateParams in WM_NCCREATE, and appends events for WM_SIZE, WM_DPICHANGED, WM_CLOSE, WM_MOUSEMOVE, WM_MOUSELEAVE, the button messages, WM_MOUSEWHEEL, WM_MOUSEHWHEEL, WM_KEYDOWN, WM_KEYUP, WM_SYSKEYDOWN, WM_SYSKEYUP, WM_CHAR, WM_SYSCHAR, WM_IME_COMPOSITION, WM_IME_ENDCOMPOSITION, WM_SETFOCUS and WM_KILLFOCUS. A failed call inside it is kept and returned by the next next.
  • WM_SETCURSOR over the client area shows the cursor with SetCursor and a system cursor from LoadCursorW; the drop, alias and context-menu cursors are the arrow, both hands are the hand, and the column and row resizes are the two-way arrows. set_cursor applies at once while the pointer is tracked inside the window.
  • open queues a Resized for the first next, and a WM_SIZE that repeats the last size or minimises the window gives none.
  • Pointer leave is requested with TrackMouseEvent on the first move, and PointerLeft comes only when it was requested. A press captures the pointer until every button is up. The extra buttons are Other(4) and Other(5). One wheel notch scrolls 48 logical pixels.
  • Every message first reads Shift, Control, Alt and the Windows keys with GetKeyState, and queues ModifiersChanged when they differ from the last reading; key events carry that reading.
  • Virtual-key codes map to Key, with ToUnicode giving the character with only Shift applied. The text of a press comes from the WM_CHAR or WM_SYSCHAR that follows it in the same drain, with surrogate pairs joined.
  • The clipboard holds CF_UNICODETEXT. Writing copies the text as UTF-16 into GlobalAlloc memory and gives it to SetClipboardData after EmptyClipboard; reading converts the locked GetClipboardData memory back to UTF-8. OpenClipboard is retried every millisecond up to ten times while another program holds the clipboard.
  • open_url joins a single-threaded COM apartment with CoInitializeEx, calls ShellExecuteW with the open verb, leaves the apartment when it joined one, and fails with Failed and the returned code when it is 32 or less.
  • Text input starts off, with the window's input context detached by ImmAssociateContextEx. set_text_input with a caret attaches the default context with IACE_DEFAULT and puts the composition window at the caret's bottom left with ImmSetCompositionWindow and CFS_POINT, and the candidate window beside it with ImmSetCandidateWindow and CFS_EXCLUDE around the caret, in device pixels; none detaches it and ends a pending composition. WM_IME_STARTCOMPOSITION is not passed on, so the system draws no composition window. WM_IME_COMPOSITION gives Commit from GCS_RESULTSTR and Preedit from GCS_COMPSTR, whose cursor is GCS_CURSORPOS converted from UTF-16 units to a UTF-8 byte offset. An empty composition or WM_IME_ENDCOMPOSITION gives an empty Preedit only after a non-empty one. A key the input method processes arrives as VK_PROCESSKEY and gives no Key.
  • A window asking for Server decorations has the system frame, and one asking for Client has none: WM_NCCALCSIZE makes the whole window the client area, inset by the frame thickness, SM_CXSIZEFRAME plus SM_CXPADDEDBORDER for the window's DPI, while maximized so the content stays on the monitor. WM_NCHITTEST then answers the resize edges and corners for points within the frame thickness of the window's border, unless maximized, and HTCLIENT elsewhere. Neither kind changes afterwards, so DecorationsChanged never arrives.
  • WM_SIZE with SIZE_MAXIMIZED sets maximized and SIZE_RESTORED clears it; tiled stays false. set_maximized is ShowWindow with SW_MAXIMIZE or SW_RESTORE, minimize is SW_MINIMIZE, and set_title is SetWindowTextW. set_fullscreen saves the style and window rectangle, clears WS_OVERLAPPEDWINDOW and covers the rcMonitor of MonitorFromWindow with SWP_FRAMECHANGED, and leaving puts both back; it sets fullscreen itself. start_move and start_resize release the capture and send WM_NCLBUTTONDOWN with HTCAPTION or the edge's hit-test code at the cursor, which runs the system's move or size loop inside the call while window messages keep queueing events. show_window_menu runs TrackPopupMenu on GetSystemMenu at the point in screen pixels and posts the chosen command as WM_SYSCOMMAND.
  • next drains the queue with PeekMessageW, and when nothing is pending waits in MsgWaitForMultipleObjectsEx with the timeout. The OS thread is in a C call while it waits, so other green threads keep running. A Waker posts WM_APP to the window; releasing the window detaches its wakers.

Renderer

  • gpu.open() -> Gpu ! Error creates a Vulkan 1.3 instance and device on the first physical device that offers dynamic rendering, synchronization2 and a graphics queue. gpu.open_for(Surface) -> Gpu ! Error also needs VK_KHR_swapchain and a queue that presents to the window, and owns the VkSurfaceKHR it makes from the Surface's display and window handles. Gpu is droppable: it waits for the device to go idle and destroys everything it made. A Target made from it is droppable too and must be released first, which using does when it is bound after the Gpu.
  • gpu.shared(g) returns a copyable Shared view of a Gpu from open_for, and gpu.open_beside(Shared, Surface) makes a Gpu for another window on the same instance and device, with its own surface, swapchain, pipelines, atlas textures and frames. Releasing it destroys those. The instance and device carry a count of the Gpus on them, kept under the queue mutex, and the last one released destroys them, so the windows close in any order; open_beside from a released Gpu fails with NoSurface. A program keeps one instance because the NVIDIA driver's Wayland swapchains break when another instance in the process is destroyed.
    • The device's queue is shared, so every Gpu on it submits, presents and waits for the device to go idle under one sync.Mutex, as Vulkan requires of queue access from several threads.
  • gpu.Error is NoDevice, Vulkan(call, result) for a failed call and its VkResult, NoMemoryType(allowed, flags) when no memory type matches, InvalidSize(width, height) for a target smaller than one pixel, and NoSurface for present on a Gpu without a window. describe(e) gives it as text.
  • A Gpu keeps two atlas textures, an R8_UNORM coverage plane and an R8G8B8A8_UNORM colour plane, that mirror the scene.Atlas it was last given, so one Gpu draws with one atlas.
  • It holds four pipelines, one per primitive kind, sharing one descriptor set layout (the instance storage buffer at binding 0, the coverage plane and its sampler at binding 1, the colour plane at binding 2) and one pipeline layout whose push constant is the target size in pixels. Each frame in flight, two of them, owns a command buffer, a fence, its semaphores and one host-visible instance buffer per kind that grows by doubling.
  • Drawing a scene writes each kind's instances into its buffer in draw order, uploads each atlas plane's dirty rows through one staging buffer, and records one vkCmdDraw of six vertices per batch, with firstInstance at the batch's first instance, inside one dynamic rendering pass that clears to the scene's background.
  • target(g, width, height) makes an offscreen Target, an R8G8B8A8_UNORM image. render(g, t, scene, mut atlas) submits a frame and returns, and read(g, t) waits for the queue to go idle and returns the pixels as RGBA bytes.
  • present(g, scene, mut atlas) draws into the next image of the Gpu's swapchain and queues it. The swapchain has a B8G8R8A8_UNORM or R8G8B8A8_UNORM format and FIFO presentation. It is made on the first call at the scene's size in device pixels, or at the surface's current extent when the surface fixes one, and made again when that size changes or acquiring or presenting reports VK_ERROR_OUT_OF_DATE_KHR or VK_SUBOPTIMAL_KHR. Each frame in flight has its own acquire semaphore and each image its own render-finished semaphore. A scene of no pixels, or a minimised window, presents nothing.
  • Colours are sRGB-encoded and blended in that space with premultiplied-free SRC_ALPHA, ONE_MINUS_SRC_ALPHA blending.
  • C structures that Vulkan reads through a pointer are pinned heap values kept by a droppable Pins list for the duration of the call or the frame.
  • The shaders:
    • Quads have per-corner radii and per-edge border widths. The fragment shader computes the signed distance to the outer and inner rounded rectangles and covers one pixel of anti-aliasing. A quad whose gradient has a direction blends its fill from background to background_end by the pixel's place on the gradient line, linearly between the two stops, in sRGB.
    • Shadows are a rounded rectangle blurred by a Gaussian of the given sigma, integrated in closed form along x and sampled four times along y, and drawn over the rectangle grown by three sigma.
    • Sprites sample the coverage plane for a monochrome glyph or shape tinted with the sprite's colour.
    • Pictures sample the colour plane, round their corners like a quad, multiply alpha by their opacity, and blend toward the Rec. 709 luminance by their grayscale.
    • Every instance carries a clip rectangle, and fragments outside it are discarded by alpha.

Scene

  • A Scene holds Quad, Shadow and Sprite instances in device pixels, each with its clip rectangle and its draw order, a counter that increases with every primitive pushed.
  • linear(bounds, degrees, from, to) gives a quad's Gradient: the line runs through the centre degrees clockwise from straight up, as geometry.direction gives it, and is |width·dx| + |height·dy| long, as CSS's linear-gradient draws it. The quad stores the direction divided by that length, in device pixels.
  • push_clip and pop_clip keep a stack of clip rectangles; each primitive takes the intersection of the stack.
  • An Atlas has two square planes of one size: coverage, one byte per pixel, written by write, and colors, four bytes of unpremultiplied RGBA per pixel, written by write_colors. Each Plane keeps the band of rows changed since clean, and clear zeroes one.
  • batches walks the four lists, each already in draw order, and merges them into runs of one kind, so primitives of different kinds that overlap draw in the order they were pushed.

Layout

  • A layout.Tree holds nodes in a slice; node(mut t, style, children) and leaf(mut t, style, measure) add one and return its index, and compute(mut t, root, available) places every node. compute_at(mut t, root, origin, available) places a root's nodes in a region whose top left is origin, so several roots can share one tree. rect(t, node) is its border box in logical pixels relative to the window and content(t, node) its content box.
  • A Style has:
    • display (Flex, or None for a node that takes no space), position (Relative, or Absolute with an Inset of one Dimension per side);
    • direction (Row or Column), justify (Start, End, Center, SpaceBetween, SpaceAround, SpaceEvenly), align_items (Start, End, Center, Stretch) and align_self (those or Auto, which follows align_items);
    • grow, shrink and basis; width, height and their minimums and maximums as Auto, Px(f32) or Percent(f32), where Percent(50.0) is half of the parent's inner size, or of its padding box for an absolute node;
    • margin, padding and border edges in pixels, and gap between children.
    • overflow_x and overflow_y: Visible, Hidden or Scroll. The layout does not clip or scroll; std/ui does, and the layout uses them only for the automatic minimum.
  • Sizes, minimums, maximums and basis are border-box lengths, and a box is never smaller than its padding and border.
  • An Auto minimum on a flex item's main axis is the automatic minimum when the item's overflow on that axis is Visible. It is the smaller of the item's definite main size and its content's narrowest main size, capped by its maximum. That narrowest size is the measure function's answer at 0.0 for a leaf, and the sum or maximum of its children's for a container in a row. In a column, it is the content's height at the item's width. An Auto minimum is otherwise zero, so a Hidden or Scroll item, or one with no content, can shrink to nothing.
  • The algorithm is CSS flexbox for a single line:
    1. Each child's flex basis is its basis, else its main size, else its content size: the measure function's answer for a leaf, the sum or maximum of its children for a container.
    2. Free space is distributed by grow when positive and taken by shrink weighted by basis when negative, freezing children that hit their minimum or maximum and repeating until none does.
    3. A child's cross size is its own, or the container's inner cross size when it stretches. Otherwise a width fits its content: its widest layout, but no wider than the room unless its narrowest layout needs more.
    4. justify places children on the main axis and align on the cross axis. Auto margins are not supported.
    5. Absolute children are placed against the padding box by their insets and do not take part in the flow. One with no inset on an axis is placed on it by the parent's justify or align_items. One with an Auto width and not both horizontal insets fits its content the same way.
  • A leaf's measure function takes the width available to it, unbounded() when unconstrained (is_bounded tells them apart) and 0.0 for its narrowest layout, and returns its size.

  • font.parse(data) -> Font ! Error reads a TrueType font with glyf outlines, or an OpenType font with CFF outlines, from the head, hhea, maxp, cmap and hmtx tables, loca and glyf or CFF , and the optional GSUB, GPOS, GDEF, kern, post and OS/2 tables. It uses a cmap subtable of format 12 or 4, preferring a Unicode one that covers every plane.
    • kern(f, left, right) takes kerning from the GPOS pair adjustment (formats 1 and 2, directly or through extension lookups) of the kern feature, else from the first horizontal kern subtable of format 0. The feature is the one of the latn script, else DFLT, else the first script, in its default language system. Its lookups apply in lookup order and the x advance of the first glyph's value record sums, the first subtable that covers the pair deciding each lookup. Device tables and the second value record are ignored, and a malformed offset gives 0.
    • substitute(f, glyphs) -> []Substituted applies the GSUB lookups of the font's ccmp feature, then those of rlig, liga and clig together in lookup order, to glyphs that are adjacent in one run. Each lookup runs over the whole sequence before the next. Single substitutions (type 1), ligature substitutions (type 4) and extension lookups holding either (type 7) are applied; other types and the lookup flags are ignored, so a ligature forms only from glyphs that are next to each other. Each Substituted has a glyph and the range first up to end of input glyphs it replaces, so a caller keeps its offsets. The script and language system are chosen as for kern. A substitute outside the font's glyphs and a subtable with a malformed offset are skipped.
    • mark_offset(f, base, mark) -> Offset? gives the x and y in font units, y up, from the origin of base to the origin of mark: the anchor of base for the mark's class minus the mark's own anchor, or none. When base is a mark it comes from the mark-to-mark lookups (type 6) of mkmk, else from the mark-to-base lookups (type 4) of mark, directly or through extension lookups. Anchor formats 1 to 3 are read as their x and y, and a malformed offset gives none. is_mark(f, glyph) is the GDEF glyph class 3, else coverage as a mark by those lookups.
    • font.parse_collection(data, index) -> Font ! Error reads font index of a ttcf collection, whose table offsets count from the start of the file; the Font keeps the whole file. parse fails with Unsupported("ttcf") for a collection, parse_collection with Malformed("header") for data that is not one or whose offset list runs past the data, and with Malformed("collection") for an index outside it.
    • It fails with Unsupported("CFF2") for a font whose outlines are in a CFF2 table, which is not read, and with Malformed(table) for a table directory entry, loca offset or CFF index that runs past the data.
    • Glyph data and lookup tables are read when used, and a malformed one gives glyph 0, an empty outline or a zero metric.
    • Font metrics (units_per_em, ascent, descent, line_gap, glyph_count) are i64 font units with y up. underline_position and underline_thickness come from post, else a tenth of the em below the baseline and a fourteenth of the em thick; strikeout_position and strikeout_size from OS/2, else a third of the em up and the underline's thickness. Positions are the top of the line. scale(f, px) converts them to pixels, and glyph_index, advance and kern look up one glyph or pair.
  • font.fallback() is Go Regular, embedded, under the Go fonts' BSD licence in std/ui/font/LICENSE.
  • font.describe(f) -> Description gives a font's family, weight and italic. The family is name 16 of the name table, else name 1, from a Windows Unicode or Symbol record in US English, else another Windows Unicode or Symbol record, else a Unicode platform record, else a Macintosh Roman one. Windows and Unicode records are UTF-16BE, and Macintosh Roman bytes from 0x80 up are converted to UTF-8 through the Mac OS Roman table. The weight is the OS/2 weight class, with 1 to 9 read as hundreds and anything outside 1 to 1000 as 400, else 700 or 400 by the head bold bit. Italic is the OS/2 italic or oblique bit, else the head italic bit.
  • font.discover() -> []Face lists the fonts in .ttf, .otf, .ttc and .otc files, matched without case, under font_directories(), ordered by path and then index within each directory. On Linux those are $XDG_DATA_HOME/fonts, else ~/.local/share/fonts, then ~/.fonts, then fonts in each directory of $XDG_DATA_DIRS, else in /usr/local/share and /usr/share; an empty variable counts as unset. On Windows they are %WINDIR%\Fonts, else C:\Windows\Fonts, then %LOCALAPPDATA%\Microsoft\Windows\Fonts. Each directory is listed once, with trailing slashes removed. discover_in(dir) lists one directory tree.
    • The walk follows symbolic links to directories and to font files, resolves a symbolic link at the root, skips a directory it cannot read and carries on with the rest, and visits each directory and each file once by device and inode, so a link cycle ends and a file reached by two paths is listed under the first.
    • A Face is a path, an index in a collection and a description, read from the table directory and the name, OS/2 and head tables alone. A file that cannot be read or is not a font is left out, and so is a font with no family.
    • open_face(face) -> Font? reads and parses one face, with parse_collection for a collection.
    • maps(face, code_point) -> bool says whether the face maps a code point to a glyph by reading only its table directory, maxp and cmap, with the same character map choice as parse. A face whose file cannot be read gives false.
  • outline(f, glyph) gives a glyph's contours of on- and off-curve points, with composite glyphs expanded through their offsets and scales, at most 6 deep and 64 components in all. rasterize(f, glyph, px) gives a Bitmap of coverage bytes with its offset from the pen.
  • A CFF glyph is the Type 2 charstring in the font's CharStrings index, run with the global subroutines and the local ones of the glyph's Private DICT, which for a CID-keyed font is picked by FDSelect (format 0 or 3) from FDArray. All path operators, flex included, the stem and mask operators (counted to skip mask bytes), callsubr and callgsubr with their bias, return and endchar run, and a width before the first stem or move is dropped because advances come from hmtx. The deprecated arithmetic and storage operators and the accented endchar are not supported, and a glyph that uses one, nests subroutines more than 10 deep, runs more than 200000 operators or has data past the end of its index gives an empty outline.
    • Each cubic curve becomes one to eight quadratic curves, split by the bound sqrt(3)/36 times the size of the curve's cubic term over the cube of the piece count, so the result stays within a tenth of a font unit of the cubic and the rasteriser keeps flattening one kind of curve. Bounds come from the outline's points, which include the quadratic control points.
  • The rasteriser scales the outline to pixels, flattens each quadratic curve into lines whose count grows with the curve's size, and accumulates each line's signed area and cover into an f32 buffer. A running sum along each row gives the coverage, clamped to 0..1 and stored as one byte per pixel.
  • font.fill(polygons, rule) runs the same accumulation over polygons already in pixels, each closed implicitly, filled by a geometry.FillRule. NonZero clamps the absolute running sum to full as a glyph does; EvenOdd folds it into a triangle wave of period two, so a pixel inside two contours is empty and one half covered by a second contour is half full. The bitmap's left and top are the pixel position of its first column and row.
  • text.System holds the fonts, the atlas and the caches. system(fonts) makes one that chooses among fonts, default_system() one with only the fallback font, and system_with_atlas(fonts, size) one with a smaller atlas. system_of(faces) makes one that chooses among discovered faces, loading each the first time it is chosen, with the fallback font as its only font of its own. add_font(mut sys, f) adds a font of its own later and returns its index.
  • A Typeface asks for a family, a weight and whether it is italic.
    • Families match without case. sans-serif, serif and monospace try the platform's usual families of that kind in order: on Linux Noto, DejaVu, Liberation and others, on Windows Segoe UI and Arial, Times New Roman and Cambria, and Cascadia Mono, Consolas and Courier New. An empty family asks for sans-serif when the system has faces, and for the first font otherwise.
    • Among the fonts of its own and the faces in a family, the slant that matches comes first, then the weight in the CSS font matching order. For a weight from 400 to 500, that order is heavier weights up to 500, then lighter weights, then heavier weights. Below 400 it is lighter, then heavier. Above 500 it is heavier, then lighter.
    • A face in the family that cannot be loaded is passed over for the next best. A typeface whose family has no loadable font gives the first font. Choices are cached by family, weight and slant.
  • A code point the chosen font does not map is drawn with the loaded font that maps it and comes first in the same order for the chosen font's weight and slant. Failing that, upright weight-400 faces are checked with font.maps, the platform's fallback families first and then the others, at most 256 per code point, and the first that maps it is loaded; one that cannot be loaded is passed over. If none does, the chosen font's missing glyph is drawn, and no face is checked again for that code point. The answer for each code point is cached until add_font.
  • Shaping maps each code point to one glyph, then, for each run of consecutive code points drawn by one font with no line break opportunity inside it, applies font.substitute, so liga ligatures such as fi form. A ligature is one glyph at the byte offset of its first code point, with the advance of the ligature glyph and an end past its last code point. It is not broken by wrapping and does not form across a font change, a space or a line break opportunity. A format applies to a whole string, so a ligature never meets a style change.
    • A mark glyph that follows a base in the same run and has a GPOS anchor for it (font.mark_offset, mark and mkmk) takes an advance of 0 and a pen position x of its base's plus the anchor offset, and a y that is the anchor's y negated, since y grows downward; a second mark attaches to the previous mark when mkmk has an anchor for the pair, else to the base. The glyph after the marks follows the base. A mark with no anchor, and a mark after a ligature, keeps its own advance and sits on the baseline. Glyphs are placed by their advances plus the kern pair adjustment when both come from one font. There is no mark-to-ligature positioning, no GSUB contextual or multiple substitution, no lookup flags, no bidirectional reordering and no complex scripts.
  • text.wrap(mut sys, s, format, width) -> Layout lays s out in a Format.
    • A Format has a typeface, a size in pixels to the em, a line_height and an align of Left, Center or Right. It also has wrap, max_lines (0 for no limit) and an ellipsis string.
    • Without a line_height, a line is the chosen font's ascent, descent and line gap. With one, the ascent and descent are centred in it.
  • Lines end at \n, \r, \r\n, VT, FF, NEL, U+2028 and U+2029. When wrapping, lines also break where unicode.line_breaks allows, by Unicode Standard Annex 14. A word longer than the width breaks between extended grapheme clusters. Spaces at the end of a line hang past it.
  • Lines past max_lines are dropped.
    • With an ellipsis, the last kept line is cut short when lines were dropped. So is an unwrapped line wider than width.
    • A cut line keeps the clusters that fit with the ellipsis, without trailing spaces, then the ellipsis. Its glyphs record the offset where the cut text starts.
    • truncated tells whether text was dropped.
  • Alignment places each line within width, or within the widest line when width is unbounded. The offset is the line's x, and its y is its baseline.
  • The layout records its line_height, the first baseline and font, the index of the chosen font. measure gives a layout's size.
  • Layouts of the same string, format and width are kept until end_frame(mut sys), and cached(sys) counts them.
  • Each glyph of a layout records its pen position x, its y below the baseline (0 except for an anchored mark), its advance, the byte offset at of the first code point it draws and the offset end past the last. A ligature draws several code points.
    • A ligature takes the highlight, colour and decoration of its first code point. The text field places its caret between the clusters of a ligature in proportion: a ligature of n clusters puts the caret after k of them at k / n of its advance, and a press picks the nearest of those positions.
  • paint(mut sys, mut scene, layout, origin, color, highlights, scale) pushes one sprite per visible glyph. Glyph origins are snapped to whole device pixels.
    • A Highlight styles the glyphs whose code points start in its byte range start up to end with any of color, background, underline and strikethrough. Each glyph takes each field from the last highlight that covers it and sets that field.
    • A Decoration has an optional color, else the glyph's, a thickness in layout pixels, else when 0 that of the font the layout chose, and wavy. Thicknesses round to whole device pixels, at least one.
    • Backgrounds are quads under the line's full height, then come the glyphs, then underlines and strikethroughs, each a quad or, when wavy, a geometry.wave stroked into the coverage plane. Glyphs on a line with the same background or decoration share one quad, which ends at the line's width, so hanging spaces are not marked.
  • The atlas planes are 1024 pixels square, each packed in shelves of its own. A glyph is rasterised at its pixel size, rounded to 1/64 pixel, the first time it is drawn, with a one-pixel border. A glyph that does not fit is left out, and so is every glyph after it in the frame; end_frame then clears the coverage plane so the next frame packs its own text.
  • paint_polygons(mut sys, mut scene, polygons, rule, color) fills polygons in device pixels with font.fill and pushes one sprite. The coverage shares the coverage plane with glyphs and is cached by the rule and the polygons' coordinates relative to the whole pixel under their first point, so the same shape moved by whole pixels reuses its tile.
  • paint_image(mut sys, mut scene, key, img, source, picture) pushes picture with its bounds snapped to whole device pixels, showing the source rectangle of an image.Image in any format. The first time key is drawn with that source and size, the pixels are cropped, converted to RGBA, resampled bilinearly to the device size and packed into the colour plane, which end_frame clears when it fills.

Presses within 500 milliseconds and 4 logical pixels of the last raise the click count. Modifiers are those of the last Key or ModifiersChanged event. on_modifiers_changed(f) receives each ModifiersChanged along the key path, from the focused element outward.

  • write_to_clipboard(cx, text) ! platform.Error and read_from_clipboard(cx) -> str? ! platform.Error reach the system clipboard of the context's window; a headless context keeps a clipboard of its own, empty until written.

  • open_url(cx, url) ! platform.Error opens a URL through platform.open_url from a window's context; a headless context opens nothing and records it, refusing what platform.is_url refuses, and opened_urls(cx) returns what it recorded.

  • window_decorations(cx) and window_status(cx) follow the window's DecorationsChanged and StatusChanged and request a frame when they change. start_window_move(cx), start_window_resize(cx, edge), show_window_menu(cx, at), set_window_maximized(cx, on), set_window_fullscreen(cx, on), minimize_window(cx) and set_window_title(cx, title) reach the window through its platform.Controls. A headless context reports Server decorations, changes its own status for maximizing and full screen, and ignores the rest.

  • window_control_area(area) makes an element part of a title bar the program draws. Drag moves the window on a left press, maximizes or restores it on a double click and shows the window menu on a right press; Close closes the window as CloseRequested does, and Maximize and Minimize act, on a click. The area acts for the topmost element under the pointer when neither it nor an element between it and the area has listeners, takes focus or can be dragged, and after the listeners when none stopped propagation. Starting a move releases the press, since the windowing system takes the pointer.

  • on_input(h) makes an element focusable and gives it an InputHandler: insert(text) replaces the composition or the selection with text and ends the composition, compose(text, selected) replaces them with a composition and selects within it, and caret(bounds) gives the caret's rectangle from the element's border box. While the element has focus, a key press whose text no binding or key listener consumed goes to insert, Commit to insert, and Preedit to compose. input_caret(cx) rounds the focused handler's caret out to whole logical pixels, and run passes it to platform.set_text_input after each batch of events. shape_text(cx, s, format, width) lays text out with the context's text system for placing carets and selections. add_fonts(cx, fonts) gives the text system fonts of the program's own, such as embedded ones, which font_family finds ahead of the system's.

  • current_cursor(cx) is the cursor of the topmost element under the pointer that sets one, above any occluding element, else Arrow. run passes it to platform.set_cursor after each batch of events.

  • Text colour, underline, strikethrough and every Format field are inherited: an element that sets none uses its parent's. The root's parent draws black text at 16 pixels in the default typeface, left aligned and wrapping, with no lines. A text element paints with its decorations over the whole text, then its highlights, all faded by the inherited opacity. A text element is a layout leaf whose measure function wraps its text with text.wrap at the width it is given.

  • A Context is a copyable handle to the state of one interface: its signals, its text system, the pointer, the pressed and focused elements and the hitboxes of the last frame. headless(background) makes one with no window, drawing text with the fallback font alone. App, made by open, holds one as app.cx beside its window and GPU and releases the GPU before the window. Its text system is system_of(font.discover()), so text uses the system's fonts.

  • open_window(app.shared(), options) opens another window as an App of its own, drawing with the first App's GPU through gpu.open_beside and with its discovered fonts. Each window has its own context and runs on its own green thread, which opens it, because a Win32 window's messages reach only the thread that made it. Windows reach each other's state through Handle.post. The windows may be released in any order.

  • Signal[T] is a shared cell owned by a context. get reads it; set and update change it and request a frame. Signals belong to the green thread that runs the context. Another green thread changes state by sending a closure through cx.handle().post(f), which runs it on the context's green thread before the next frame and wakes the window through its Waker.

  • cx.memo(compute) returns a Memo[T] for any T with Eq, and read returns its value. A memo computes on its first read and again on a read after a signal or memo it read has changed. When it recomputes to an equal value, nothing that reads it runs again. cx.effect(f) runs f at once and again whenever a signal or memo it read changes; dispose stops it. A changed effect runs once at the end of the dispatch that changed it, or at the start of the next frame, however many of its sources changed. An effect that changes a signal another effect reads makes that one run in the same pass, and an effect that changes a source of its own runs again in it. A pass that is still running effects after 100 rounds panics, since effects that keep changing what each other read never settle.

    • Every signal, memo and effect is a node. A memo or effect records the nodes it reads while it runs. Each run starts a new generation and drops the earlier links, so a read that a branch skips no longer counts; a node keeps one link per reader, and recording a read drops the links of readers that have run since or been disposed. A node is clean from the start of its run, so a change during the run marks it again. Changing a signal marks its readers dirty, and the readers of a dirty memo as needing a check. A read or an effect run checks the memos it depends on in order and recomputes only after a source has really changed.

  • cached(cx, key, build) returns an element that stands for a view: what build returns, built again only when a signal or memo it read during its last build has changed, or the focus, pending keys, drag, a scroll offset, or the window status or decorations have, which the context reads as one node. Layout resolves the placeholder to the view's element, so a cached view inside another rebuilds alone and its parent keeps its own element. A view no frame lays out is dropped, and build holds the element's builders, because the placeholder is replaced. Layout and paint still run over the whole tree each frame.

  • frame(cx, render, size, scale) calls render, builds a layout.Tree from the elements, lays it out in full at size logical pixels and paints it into a scene.Scene of scale device pixels per logical pixel, whose size is size times scale rounded to whole pixels. dispatch(cx, event) applies a platform.Event. run(app, render) loops until the window is closed or quit is called: it waits for events with platform.next, dispatches them, and when a frame is due calls frame and gpu.present. draw(cx, g, target, scene) renders a frame offscreen.

  • A frame is due when any of these has happened since the last one:

    • a signal has changed, or a closure has been posted
    • the window has changed size or scale
    • the set of hovered hitboxes has changed, or a press or release of the primary button has happened
    • focus has moved, or a scroll offset has changed

    A change made while render runs requests the next frame. An animation that is running requests the next frame as soon as one is drawn. run then polls for events instead of waiting.

  • Building the layout tree resolves animations. An element with with_animation is replaced by what its function returns for the animation's progress:

    • Animation has duration_ms, repeat and easing.
    • Progress is the time since the first frame that built an element with that id, divided by the duration, wrapped when repeating and held at 1.0 otherwise, then passed through easing.
    • An id that a frame does not build is forgotten.
    • The easings are linear, quadratic, ease_in_out, ease_out_quint, bounce(easing) and pulsating_between(low, high).

  • A frame walks the resolved tree twice:

    • The first walk records a hitbox for each element with a listener, a state, a group name, a key context, focusable, occlude, a tooltip, a drag or a scrolling overflow. A hitbox holds the element's border box within the clip, its key, the index of its nearest ancestor's hitbox and, for a scrolling element, its scroll offset and range. The key is the element's id, else its position in the tree as 0/2/1 under the nearest ancestor with an id.
    • A deferred box is laid out where it stands but walked after the rest of the tree, without its ancestors' clips. Deferred boxes are walked by ascending priority, then in tree order, and deferred boxes inside them after those. Their hitboxes are recorded last, so they are topmost.
    • The hit test then marks the hitboxes under the pointer, from the last recorded down to the first, stopping after one that occludes.
    • The second walk paints in the same order. For each element it draws the shadows, the background and border as one quad and the text as sprites, then the children inside its padding box on each axis that does not overflow Visible. Opacity multiplies down the tree into every colour an element and its descendants paint.

  • An anchored(spec) box is absolute, sized by its children, and moved with them so that spec.corner sits at spec.position + spec.offset. With no position it uses where the layout put the box.

    • When spec.snap is set, the box slides inside the window, keeping spec.margin from its edges.
    • Otherwise, on an axis where it would cross the window's edge, it flips to the other side of the point if it fits there.

  • A tooltip appears once the pointer has rested on the topmost marked hitbox with a tooltip for 500 milliseconds. It is the element tooltip's function makes, anchored 20 pixels below where the pointer was then, snapped 8 pixels inside the window, and painted above every deferred box. It goes when the pointer leaves that hitbox or a button is pressed, and stays away until the pointer leaves.

  • A primary press on an element with on_drag, or inside one, arms a drag. Once the pointer moves 2 logical pixels, the drag starts:

    • preview's element follows the pointer, grabbed where the press was, above everything.
    • drag_over holds for marked hitboxes.
    • active_drag(cx) returns the value.
    • The release runs on_drop listeners on the marked hitboxes, bubbling like a click, in place of the click.

  • A state holds as follows:

    • hover: while the element's hitbox is marked.
    • active: from a primary press that marked it until the release.
    • focus: while its key is focused. in_focus: while it or a descendant's key is focused.
    • group_hover and group_active: while the nearest enclosing element with that group name, itself included, is hovered or active.

  • Mouse events bubble through the marked hitboxes from the last recorded down, and a listener's stop_propagation(cx) stops them:

    • Presses and releases reach on_mouse_down and on_mouse_up listeners for their button.
    • Every press runs the on_mouse_down_out listeners of unmarked hitboxes.
    • A primary press focuses the nearest focusable element from the topmost marked hitbox outward.
    • A primary release runs on_click on marked hitboxes that its press also marked.

  • Wheel events run on_scroll_wheel listeners on the way. A scrolling element under the pointer that can move takes the delta and stops the event, so an inner list scrolls before the page holding it.

  • Scroll offsets are kept by key. Each frame clamps them to the distance the children's border boxes reach past the padding box, and shifts the children and their hitboxes by them. scroll_offset(cx, key) reads one and scroll_to(cx, key, offset) sets one.

  • A uniform_list scrolls vertically and builds only the items it shows:

    • After the tree is laid out, each frame lays out items(0, 1) at the list's content width to find the item height.
    • It then calls items(first, end) for the items its content box shows at its scroll offset. Each is laid out as a root of that height at the content width, below the ones before it.
    • Its scroll range reaches count items. An item with no id is keyed <list id>/<index>, so its state follows the item as the list scrolls.
    • scroll_to_item(cx, id, index) scrolls the least distance that shows the item, using the item height and view from the last frame.

  • A list(state, item) scrolls vertically through items of any height, building only those it shows:

    • list_state(cx, count, alignment) makes the ListState that holds the item count, the heights of items laid out at the current width, and the scroll position as a ListOffset: the item at the top of the view and how far into it the view starts. Copies share it, and changes to it request a frame.
    • Each frame lays out item(i) from the top item down until the view is full, each as a root at the content width and its own height. When the items run out before the view is full, the list scrolls back so the last item ends at the view's bottom.
    • Wheel deltas and scroll_to move the top item by the measured heights, estimating unmeasured ones as the mean of the measured. The pixel scroll offset and range are derived from the heights each frame, so items above the view that change height do not move what is shown.
    • With Bottom alignment, a list shorter than its view sits at the bottom, the list opens at its end, and a list showing its end stays there as items arrive. With Top alignment it starts at the top.
    • reset(s, count), splice(s, from, to, count), item_count, logical_scroll_top, scroll_to_offset(s, offset) and scroll_to_reveal_item(s, index) change or report the state. A splice keeps the top item in place. An item with no id is keyed <list key>/<index>.

  • A canvas(paint) is laid out like a div with no children. When the frame paints it, after its own box, paint receives a Painter with the canvas's border box as bounds, its inherited text format and its inherited text color, which the frame fades by the inherited opacity like every mark. paint_quad and paint_shadow add marks in logical pixels, which the frame scales, fades by the inherited opacity and clips like the canvas's own box.

    • paint_path(path, color) fills a geometry.Path by the nonzero rule, paint_path_evenodd(path, color) by the even-odd rule, and paint_stroke(path, width, color) traces it with a round pen. All rasterise at the frame's scale into the coverage plane.
    • paint_underline(origin, width, thickness, color, wavy) adds a quad, or when wavy is set the stroked geometry.wave(origin, width, thickness).

  • render_image(cx, pixels) names decoded std/image pixels as a RenderImage, and img(source) draws one. Its content size is the image's, one logical pixel per image pixel, scaled down to the width available keeping its shape. object_fit places it in the content box: Contain, the default, Fill, Cover, ScaleDown or Unscaled. The part outside the box is cropped before resampling, the corners follow rounded, and the inherited opacity and grayscale apply. An image is resampled once per size and kept in the atlas's colour plane until it fills, and one larger than the plane is not drawn.

  • A geometry.Path is built by path(), move_to, line_to, quadratic_to, cubic_to and close. flatten(p, scale) gives its contours as polygons of more than two points, curves split into lines within 0.05 pixels of them, at most 128 per curve. stroke(p, width, scale) gives a disc at every point and a band along every line, all wound the same way, so their nonzero union is the round-joined, round-capped stroke; only a closed contour joins its last point to its first. wave(origin, width, thickness) is an open path of quadratic curves swinging thickness either side of the line thickness / 2 below origin, one whole wave every six thicknesses. segments(p) gives its steps as Segment values (Move, Line, Quadratic, Cubic and Close), and affine(p, a, b, c, d, e, f) moves every point (x, y) to (a * x + c * y + e, b * x + d * y + f).

  • svg.parse(source) reads an SVG document into an Icon: a view_box and the shapes in paint order, each a geometry.Path in view box units with its fill and stroke paints (None, Color(c) or Current), stroke_width, opacity, fill_opacity, stroke_opacity and fill rule, a geometry.FillRule (NonZero or EvenOdd). It does not import std/ui.

    • The view box is viewBox, else 0 0 width height from width and height given as plain or px lengths, else 0 0 24 24.
    • path reads every command, M m L l H h V v C c S s Q q T t A a Z z, with implicit repeats (a repeated M is a line), numbers and arc flags written without separators, and a move after Z starting at the contour's start. An arc becomes cubic curves of at most a quarter turn. rect with rx and ry, circle, ellipse, line, polyline and polygon become paths too, inside any number of g and nested svg elements. Any other element is skipped with its content.
    • fill, stroke, stroke-width, opacity, fill-opacity, stroke-opacity, fill-rule and display come from attributes and from the declarations of style, which win. A child inherits them, except that opacity multiplies down the tree and transform composes. Colours are #rgb, #rgba, #rrggbb, #rrggbbaa, rgb() and rgba() with numbers or percentages, the CSS basic colour names, none and currentColor; url(...) paints nothing. The default fill is black and the default stroke is none.
    • transform takes translate, scale, rotate, skewX, skewY and matrix, applied to the path's points. The stroke width is multiplied by the square root of the transform's determinant. A stroke is always round-joined and round-capped, and dashes are not drawn.
    • Error is Syntax(line, column, message) for XML that does not parse, NotSvg(name) for another root, BadNumber(attribute, at) and BadPath(at) with the byte offset in the value, and BadValue(attribute) for a colour, fill-rule, transform or view box that is not understood.

  • svg_icon(icon) is a canvas with no size of its own, so the caller sizes it as svg_icon(icon).size(16.0, 16.0). It scales the view box into its border box, keeping the shape and centring it, as preserveAspectRatio="xMidYMid meet" does. Every shape that has a fill or a stroke is drawn in the inherited text colour, with the alpha of its own colour, opacity, fill-opacity or stroke-opacity and the inherited opacity applied, whether the document says currentColor, names a colour or leaves the fill at its default of black; the colours a document names are kept in the Icon and not drawn. A shape with the EvenOdd rule fills with paint_path_evenodd.

  • The key path runs from the focused element's hitbox through its ancestors' hitboxes, or from the root's when nothing is focused. Its elements' key contexts, outermost first, form the context stack.

  • bind(cx, keys, action, context) adds a binding, and fails with BindError when the keystrokes or the predicate do not parse:

    • keys is one or more keystrokes separated by spaces. A keystroke is any of ctrl, alt, shift and super (also cmd or win), each followed by -, then a character or a named key such as enter, space, pageup or f5.
    • A key context is space-separated names and key=value pairs. In a predicate, a name holds when the innermost context of the stack has it; key == value when that context has the pair; key != value when it lacks the key or holds another value. !, &&, || and parentheses combine them, binding in that order of strength, loosest last. a > b is loosest of all: b holds on the stack and a on a shorter prefix of it.
    • A binding's depth is the length of the longest prefix of the stack its predicate holds on, 0 for an empty predicate.

  • A key press first goes to the bindings:

    • A binding counts when its predicate holds somewhere on the stack and its action has a handler on the key path or from on_app_action.
    • Bindings rank by depth, deepest first, then the later bound first.
    • While a counting binding is longer than the keystrokes typed and starts with them, the press waits as pending. pending_keys(cx) shows the wait.
    • A press that completes a binding runs the action of the best-ranked one whose handler runs. A binding to the action "" ends the search, so it hides the bindings of the same keys it outranks.
    • A press that continues no binding, or one after a pending press has waited a second, replays the pending presses one at a time against single keystrokes, and then is tried afresh.
    • A press with Shift held also matches a keystroke without shift whose key is the character the press names, so ? matches Shift+/ and ctrl-? matches Ctrl+Shift+/.

  • An action reaches the on_action handlers on the key path, innermost first; the first handler stops it unless it calls propagate(cx). The on_app_action handler runs when no handler stopped it. dispatch_action(cx, name) dispatches one directly. is_action_available(cx, name) and bindings_for(cx, name) report what the key path offers.

  • A press no binding takes, and every release, bubbles along the key path through on_key_down or on_key_up listeners until one calls stop_propagation. An unstopped Tab or Shift+Tab press moves focus to the next or previous focusable element in tree order.

  • Focus is kept by key across frames. set_focus(cx, key) and blur(cx) move it.

  • Tasks run work away from the context's green thread and deliver to it. Each returns a copyable Task that cancel_task stops, and closing the context, by CloseRequested or quit, cancels them all through a parent cancel.Token.

    • background_task(cx, work, done) runs work(token) on a green thread of its own, which the scheduler may move to another OS thread, and posts done(result). work can watch the token with cancel.check or cancel.pause.
    • after(cx, ms, f) posts f once ms milliseconds have passed, and every(cx, ms, f) every ms milliseconds.
    • A posted callback checks the token again on the context's green thread, so a task cancelled there runs nothing more.

  • set_clock(cx, clock) replaces time.monotonic as the source of time for animations, tooltips, double clicks and pending keystrokes, so a test can step time.

  • closed, frame_due and focused report the context's state.
